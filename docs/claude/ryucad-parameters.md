## Parameters and expressions (decided in ryucad phase 2)

The design is document 36 in the Coxswain planning project `ryucad-ryukei`; this is its phase 1.

- **Expressions.** Anywhere a quantity goes, a string may be an expression (`ryucad::expr`): literals with units (`3 mm`, `15 deg`; angles are `deg` and `rad`), parameter names (`[a-z_][a-z0-9_]{0,62}`, not a unit, function or `pi`), `+ - * / ^`, parentheses and the functions in `expr::FUNCTIONS`, all from `ryukei::math`. A string that is only a number takes the default unit, as in phase 0; inside an expression a bare number is a plain number, so `wall + 3` is `unit_mismatch`. Values carry a dimension (`units::Dim`, powers of length and angle); syntax faults are `invalid_quantity` with a byte `position`. Text is kept token for token with canonical spacing (`2 * wall + 3 mm`), and output adds `"expr": true` to a quantity that isn't a literal.
- **Parameters.** `parts/<part>/parameters.json` (kind `ryucad.parameters`) holds a part's parameters, each an expression over the others (`expr::Env`; cycles are `parameter_cycle`). The part's revision covers it. Features are evaluated against it when the part loads, so `Quantity` holds its value; a feature whose parameter is missing or broken fails alone. A feature with any expression is written at feature format 2, one with only literals at 1.
- **Protocol.** `param.list`, `param.set`, `param.delete` (refused with `has_dependents` while anything reads it; the file goes with its last parameter) and `param.rename` (rewrites every expression that reads it, in one logged change). Writes refuse values that don't evaluate or that would break a feature that loads now.

## Project parameters (decided in ryucad phase 10)

The design is document 198 in the Coxswain planning project `ryucad-ryukei`; this is its phase 8, plan 10.E.

- **The file.** A `parameters.json` at the project's root (kind `ryucad.parameters`, as a part's) holds the project's parameters, expressions over each other with a part's names, units, functions and cycle rules. It is a root file (`doc::project::ROOT_FILES`): sessions track it, Git revisions read it, and a change to it reloads every part. `Project::parameters` holds it (or why it doesn't read), `Project::env` its values.
- **Reading them.** The project's values are the scope around every part's (`expr::Env::within`): a part's parameters, features and explodes read a project parameter by its plain name. A part parameter named as a project parameter is `parameter_shadows` (new code): refused when either is written (`param.set` of either scope, `param.rename`), and where a file has one anyway (a merge, an edit by hand) it and everything reading it fail with it, and doctor reports it once (an error, no repair). A project file that doesn't read fails every name a part reads from it, naming the file.
- **What a part reads.** `Part::project_reads`: the project parameters its listed features, its own parameters and its explodes name and it doesn't have itself, closed over what those read (`doc::project::project_reads`; `reads_in` reads the same from files). A part's revision adds, last and tagged (`ryucad.project_parameters`), each one's name and text in name order, with each of its own parameters' names the project also has and the project's text for it (`doc::project::shadowed`: a shadow is a fault, so the revision, the release content hash and merge blame (`validate::touched`) all move when the project gains or loses one, and a cached rebuild never outlives it), so a part reading and shadowing none hashes as before; while the project's file doesn't read, a part reading a name it lacks hashes that file's bytes. Recompute keys needed no change: they already hash the values of the names a feature reads, now found in either scope, so a change rebuilds exactly the parts whose values moved (beyond the design, which said text: values decide results).
- **Releases.** The release content hash gains a sixth piece (see `ryupdm.md`); a part pinned at a label reads the project's parameters as the release's commit has them (`Session::pinned_part` takes the root file with the part's).
- **Protocol.** `param.list`, `param.set`, `param.delete` and `param.rename` take `scope: project` instead of a `part` (both, or neither, is `usage`), CLI `ryucad param … --project`. Project writes are guarded by the project's revision (which now covers the root file, tagged) and checked as a part's are, every part's features that load now still loading; `param.set` keeps current the sketches and assemblies of every part whose results the names may move (each kept sketch named with its `part`); `param.delete` is `has_dependents` while a project parameter or a part reads it (`parts`); `param.rename` rewrites every part's parameters, feature files and explodes that name it, and the root file, as one logged change. `param.list` of a project gives each parameter's `used_by: {parts, parameters}`; of a part, `project_parameters`, the ones it reads. `project.changed` carries the project's parameters as written when it has any, so a window hears of one no part reads.
- **Git and doctor.** See `ryucad-git.md`. Doctor reads the root file as a part's (`invalid_document`, `non_canonical`) and checks every part's features in its scope; a sketch's staleness counts the root file among its files.
- **Testing.** `expr` (scopes, shadows), `doc::project` (loads, reads, revisions, shadows, a broken root file), `param.rs` (both scopes, refusals, a rename as one change, sketches kept current, a shadow written by hand failing the part's rebuild), `config.rs`, `assembly.rs` (a label pins the parameters as released, and the release goes `modified`), `doctor.rs`, `diff.rs`, `validate.rs`, `server.rs` (the notification); `tests/cli.rs`'s `project_parameters_from_the_cli` both ways; `tests/recompute.rs`'s `project_parameters_recompute_as_from_nothing` (1 and 8 threads, a part reading nothing keeping its revision); the `feature` fuzz target's features read `wall` and `gap`.

## Equations (decided in ryucad phase 10)

The design is document 198 in the Coxswain planning project `ryucad-ryukei`; this is its phase 9, plan 10.E.

- **`equations.list`.** `ryucad equations [PART] [--all] [--rev REV]` (`crate::equations`): the project's parameters, then a part's (else every part's, in ID order) parameters and, for each listed feature in order, its expression fields in pointer order, each a row `{scope, part?, what, name | feature + type + pointer (+ constraint), text, value? | error?, reads}`: `what` is `parameter`, `field`, or `dimension` for a sketch's constraint. Fields are read from the feature's file, so a feature that fails says why. Without `--all`, fields holding a plain literal are left out (parameters never are). The answer gives `revisions: {project, parts}`, which writes from the table are guarded by.
- **Writing a row.** A parameter through `param.set` (its scope), a sketch's dimension through `sketch.edit` (`set`), and a feature's field through `feature.edit`'s new `expressions` (CLI `--expr POINTER=EXPRESSION`, repeatable): expressions by JSON pointer, each one of the feature's expression fields (`doc::files::expression_fields`), given alone (with other fields `invalid_param`); a sketch's are refused there (they are solved), as are imports.
- **Testing.** `equations.rs` unit tests (the table, `--all`, every part, failures, a dimension, edits by pointer and their refusals), `doc::files`' pointer test, and `tests/cli.rs`'s `equations_from_the_cli` both ways.

## Unused parameters (decided in ryucad phase 23)

The design is document 447 in the Coxswain planning project `ryucad-ryukei`; these are its phases 3 and 4, plan 23.B (#672).

- **What reads a parameter.** `doc::reads` (ryucad-doc, pure): a part's parameter is read when a listed feature (a sketch's dimensions included) or an explode reaches it, directly or through the part's other parameters; a project parameter when some part's features or explodes reach it, through that part's parameters and the project's. Closed transitively, so a parameter read only by unused ones is unused, a project parameter read only through an unused part parameter included (beyond the design, which named `Part::project_reads`: that set also holds what unused part parameters name, and stays what a part's revision hashes). `in_project` reads a loaded project, `in_source` any `Source` (the folder, a revision's files), the same. `Part::explode_uses` keeps what each explode's text names, as `uses` does for features, so a broken explode still reads.
- **Doctor and check.** `parameter_unused` (a warning, no repair: deleting is the author's call, and the message names `ryucad param delete`): once for the project's (`scope: project`, `files: [parameters.json]`) and once per part (`part`, its `parameters.json`), with `parameters: [{name, read_by, error?}]`, `read_by` the unused parameters naming it. A parameter that doesn't evaluate and that nothing reads is still listed, with `error` (nothing else reports it: one something reads fails its reader). A name both scopes have is `parameter_shadows`'s, never unused. Doctor issues gained `details`, joined into their reports, so `check` carries the fields with `source: doctor` and passes. `param.list` adds `unused: true` (both scopes).
- **diff.** Every added, removed or changed parameter, a part's and the project's, gains `read_by: {from, to}` (features by ID, explodes as `explodes/<id>`, parts by ID, through parameters) and `unused: true` when both are empty. The project block's `parts` is unchanged: what rebuilds, not what reads. Textconv is unchanged.
- **The app.** The Parameters tile puts a weak `unused` under a parameter `param.list` marks, the reason on hover (`form::Rows::mark`); the Changes tab lists the chosen feature's part's and the project's parameter changes (`compare::ParamChange`), those nothing reads weak with `(read by nothing)`.
- **Testing.** `doc::reads` unit tests (scopes, transitivity, files against a loaded project), `param.rs` (both scopes, a broken one), `doctor.rs` (direct, transitive, project scope, an explode reading one, a broken one, shadows), `check.rs`, `diff.rs` (both sides, `unused`, the project's), `tests/cli.rs`'s `unused_parameters_from_the_cli` (#672's heatsink, both ways), the app's `core::params` and `core::compare` and `tests/params.rs` against a daemon.
- **As built.** As planned; no existing test met `parameter_unused` or a `read_by`, so none changed.
