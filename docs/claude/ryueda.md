## Projects and the library (decided in ryueda phase 0)

The design is document 157 in the Coxswain planning project `ryucad-ryukei`; this is its plan 0.B.

- **Crate.** `ryueda` (library and binary) depends on `ryu-doc`, `ryu-session` and `ryu-part21`, never on ryukei, ryustep or ryucad. It is a product of `ryu-session` (`ryueda::Eda`: `RYUEDA_RUNTIME_DIR`, `RYUEDA_CONFIG_DIR`, `RYUEDA_IDLE_TIMEOUT`, topics `project`, `participants`, `activity`, the preference `daemon.poll_ms`), and `ryueda version` (`ryueda`, `commit`, `target`, `protocol` 1) names no ryucad, so neither product's client takes the other's daemon. The CLI prints ryucad's envelope and exit codes; every protocol method has a command (a test fails otherwise), and CLI scenarios run in process and through the daemon alike.
- **Projects.** `ryueda.json` (kind `ryueda.project`, format 1): `project` (a ryupdm project ID, random at `init`), `default_unit` (`mm` by default; the length unit of bare numbers), `project_kind: library` for a library project (left out for a design project), and `libraries`: `{alias: {path}}`. `init` refuses a folder holding a ryueda or ryucad project (`project_exists`). Files are canonical JSON with `kind` and `format`, read by serde with unknown fields refused (`invalid_document`) and newer formats `format_too_new`.
- **Library projects.** An alias's path is relative, `/`-separated, with no empty, `.`, `\` or `:` parts; it resolves (canonically, so through no symlink out) to a library project inside the repository holding the project, else inside its parent folder, that names no libraries of its own. Otherwise the alias is `library_missing` (or `library_nested`) and fails only what names it. A library project names no aliases, and its files name only their own library (`library_nested`). `lib add` refuses an alias that doesn't resolve now, `self` and duplicates; `lib list` gives each library's revision, counts and faults. Writes go to the project's own library (`self`) only: a library project is edited by running ryueda in it.
- **Revisions and sessions.** A library's revision is a BLAKE3 over its files' paths (within `library/`) and bytes, the project's over its manifest, 32 hex each; writes take `--expect` (`conflict`). The session tracks the manifest, `library/` and each usable alias's manifest and `library/` (as `../<path>/…` paths), reloading on any change. The activity log keeps only the project's own files (an alias's come into view when named, and undo must never delete them); `undo`, `redo` and `history` (the activity log) need the daemon. `project.changed` carries `{revisions: {project, lib/<alias>…}, changed}`.
- **Coordinates and IDs.** Lengths are integer nanometres and angles integer millidegrees. A typed quantity (`"0.5 mm"`, `"100 mil"`, `"90 deg"`; units nm, um/µm, mm, cm, m, mil, in, ft; a bare number in the default unit; no radians) converts from its decimal text exactly and rounds half to even once (`coord::exact`, which plan 0.D's import uses); a bare integer is already nanometres or millidegrees. Library objects take readable IDs from their names (`name::readable`: lowercase ASCII, other runs one `_`, at most 56 characters, `item` when empty), `-2`, `-3`, … on a collision. `ryu-doc`'s `Id` and `ProjectId` deserialize as `parse` checks them.
- **Symbols.** `library/symbols/<id>.json` (kind `ryueda.symbol`): `name`, `units`, `pins` by number (`name`, `type` in KiCad's twelve, `unit` or none for every unit, `at`, `side`, `length_nm`, `shape` in KiCad's nine, `alternates`) and `graphics` by `g<n>` (`rect`, `polyline`, `arc` through three points, `circle`, `bezier`, `text`, each with `fill` and `unit`), no colours or widths. Checks (`library_unit_invalid`, `library_pin_invalid`, `library_graphic_invalid`, `library_out_of_range` past a metre) carry a JSON pointer; a symbol with no pins at all is a drawing, but each unit of several needs a pin of its own. `symbol create` (a name and `--ops`) and `symbol edit` apply batches of `add`, `remove`, `set` and `move` ops on pins (by number; `set` may renumber) and graphics (by ID, `add` taking the next), all or nothing, with lengths and angles under `at`, `length`, `radius`, `size`, `rotation`; a write that adds a check's error is refused with every fault, the first's code its own. Removing or renumbering a pin of, or deleting, a symbol a library component of this library places is `has_dependents`; a pin added is reported against the components using it.
- **Footprints.** `library/footprints/<id>.json` (kind `ryueda.footprint`): pads by ID (`number`, `kind` `smd`/`through`/`connector`/`npth`, `shape` with KiCad's seven including trapezoid, roundrect, chamfered and custom primitives, `drill` round or slot with offset, `layers`, margins, `thermal`, `property`, `die_length_nm`), graphics (`layer` and a shape with `width_nm` and `fill`; widths are physical, not style), keepouts, the `reference` and `value` fields' places, `mount`, KiCad's attribute `flags` and `models`. Layers: `copper.top|bottom|inner|all`, the top and bottom of `mask`, `paste`, `silk`, `fab`, `courtyard`, `adhesive`, and `user.1` to `user.45`. Checks: `library_pad_invalid` (sizes, ratios, a drill inside its pad in the pad's frame, drills only on through and NPTH pads, custom polygons simple by exact integer tests), `library_graphic_invalid`, `library_layer_unknown`, `library_out_of_range`, and a warning, `library_courtyard_missing`, unless `allow_missing_courtyard`. No command writes footprints; `footprint show|list` read them.
- **Models.** A model is `{"step": {path, blake3}}` (an enum, so stage 9 adds ryucad parts) placed by `offset_nm`, `rotation_mdeg` and `scale_ppm`. The file must be `library/models/<id>.step` of the footprint's own library (`model_file_missing`), its bytes the BLAKE3 named (`model_file_changed`), and a Part 21 exchange structure (`model_unreadable`, checked by `ryu-part21` once per BLAKE3 per process). The activity log counts `library/models/` against its bulky budget.
- **Library components.** `library/components/<id>.json` (kind `ryueda.libcomp`): `symbol` and each of `footprints` as `{library?, id}` (no `library` for the file's own), `prefix` (letters), `value`, `description`, `datasheet`, `parameters` (text as written), `manufacturer`, `mpn`, `offers` (`[{supplier, sku}]`), each footprint with `pins`: a symbol pin to its pads, a pin left out to the pad of its number. Checks, judged once every library is loaded: what doesn't resolve (`not_found`, `library_missing`, `library_nested`) where it is named, `pin_not_found`, `pin_without_pad` (`no_connect` pins excepted), a mapped pad the footprint lacks (`not_found`), `pad_mapped_twice`, and the warning `pad_without_pin`. `libcomp create|edit|show|list|delete`; an edit replaces the fields given and merges parameters (`--unset-param`).
- **Testing.** Unit tests per module (coordinates at their edges, readable IDs, each file kind's round trip and refusals, every check firing, ops, libraries, aliases, sessions), and `tests/cli.rs`: projects and library projects, the activity log and undo through the daemon, a watcher hearing of a library, symbols, footprints and library components from the CLI, and protocol parity.

## Connectivity and ERC (decided in ryueda phase 0)

The design is document 157 in the Coxswain planning project `ryucad-ryukei`; this is its plan 0.C.

- **Files.** `designs/<id>.json` (kind `ryueda.design`: `name`, `root` block), `blocks/<id>/block.json` (`ryueda.block`: `name`, `description`, `ports` by ID with `name`, `direction` (`in`, `out`, `bidirectional`, `power`, `passive`) and an optional `voltage` the block expects, `buses` by ID with `name` and `nets`), and in a block's folder `components/<id>.json` (`ryueda.component`: `of`, `refdes`, `footprint` as the library component lists it, `value`, `parameters`, `pins` by number), `nets/<id>.json` (`ryueda.net`: `name`, `class`, `voltage`, `current`, `impedance`, `pair` `{with, polarity}`) and `instances/<id>.json` (`ryueda.instance`: `of`, `ports`, `refdes` `{rule: suffix | offset, value}`, `overrides` by occurrence path below it); `rails/<id>.json` (`ryueda.rail`: a net's fields but `pair`) and `classes/<id>.json` (`ryueda.class`). All format 1. What a pin or an instance's port connects to is a block net's ID, `{"rail": id}`, `{"port": id}` or `"nc"`; no net may take the ID `nc`. A pin names a port directly: a port is a net of its block, joined through the instance to what its parent maps it to. Intent quantities are `ryu-doc` electrical literals, compared exactly from their decimal text (`conn::exact_value`: `3.3 V` is `3300 mV`).
- **IDs.** Design objects (blocks, components, nets, instances, ports, buses, rails, classes, designs) take random IDs, 10 lowercase base32 characters from 50 bits of the OS's randomness, or one the agent chooses; `RYUEDA_ID_SEED` makes them a fixed sequence, each the first of the seed's not taken, so a project's files give the same IDs in any process, in a daemon or not (`name::random`). A block's components, nets and instances share one ID space, so `<block>/<id>` names one object.
- **Loading and faults.** `design::load` reads every file in parallel with its own checks; `Connectivity::judge` adds what files name of each other: nets, rails and ports pins and instances name, nets' classes and pairs, instances' blocks, ports and overrides, a design's root, each component's library component (`self`'s, or an alias's), names unique among a block's nets and ports and the rails (`net_name_duplicate`), and blocks that contain themselves (`block_cycle`, with the chain, on every instance closing one). A block folder holding no files (what undoing its creation leaves) is no block. The project's revision hashes its manifest, `erc.json`, designs, rails and classes; each block's (`block/<id>` in `project.changed`) its folder's files.
- **Writes.** A write works out the files it changes, reads the project again over them in memory, and goes to disk only if that adds no error to any file (by code, path and pointer), refused otherwise with the first new fault's code and every one in `faults`; the session then adopts the project it judged rather than reading it again. Specific refusals come first: `pin_not_found` (the symbol's pins), `net_not_found`, `port_not_found`, `not_found`, `duplicate_id`, `net_has_pins` (`net.delete` while pins or ports name it), and `has_dependents` (a rail, class, port, block, pair half or library component something still names). Block-level writes are guarded by the block's revision, the rest by the project's. Requests: `block.create|edit|show|list|delete` (ports and buses by ops), `component.add|edit|delete|show` (a refdes is the prefix and the project's smallest free number unless given), `connect` (`<block>/<component>/<pin>` to a net by ID or name, `rail:<…>`, `port:<…>`, or with `new` a new net), `disconnect`, `nc`, `net.add|edit|rename|join|delete|show` (`net.edit` pairs both halves; `net.join` moves every pin and port on a net onto another net of its block or a rail, and its buses' memberships, in one change), `instance.add|edit|delete|show`, `rail.*`, `class.*`, `design.create|edit|delete|list`, each a CLI command. `libcomp.delete` is refused while a design places the component, and a symbol edit that removes a pin lists the design pins it connects among its `dependents`.
- **The netlist.** `netlist::flatten` walks a design from its root, depth first, instances in ID order, components gathered per block occurrence in parallel; every port climbs to what its instance maps it to, so each flattened net has one highest node: a rail, a block net, or an unmapped port. References: an occurrence is `<design>:<instance>/…/<component>`, a pin adds `/<pin>`, a net `<design>:<path>/<net>`, `<design>:<path>/port:<port>` or `<design>:rail:<rail>`; a net's name is the rail's, or the instance path and the net's or port's name, unique by the name rules. A reference designator applies each instance's rule from the innermost outward, an override replacing what its instance's rule would give. Each pin lists its pads on the component's footprint. A design reads as its files are or not at all: any error in its design file, the blocks it reaches or the rails refuses it, with every fault. Derived data, never written.
- **ERC.** `erc::check_netlist` over a netlist, findings `{id, code, severity, design, refs, message, details, waived?}` sorted by code then references, each ID 16 hex digits of BLAKE3 over its code, design and sorted references. `pin_conflict` (KiCad's default matrix, `free` with anything, open collector with open emitter allowed; each pair of types once per net, at the matrix's severity unless `erc.json` sets one), `power_undriven` (power inputs with no power output, rail or power port), `pin_unconnected`, `nc_connected` (a `no_connect` pin on a net), `net_single_pin` and `input_undriven` (not for a net reaching an edge: a port of the root block, driven from off the board), `refdes_duplicate`, `refdes_missing`, `footprint_missing` (none to take, or one the library component doesn't list), `pin_without_pad` and `library_fault` (once per placed library component, its own, its symbol's and its footprints' errors), `pin_not_found` (a pin its symbol lost), `pair_unmatched`, `intent_conflict` (a net's or rail's voltage against the ports it passes through), and `waiver_unused`.
- **`erc.json`.** Kind `ryueda.erc`: `severity` by code (`error`, `warning`, `off`) and `waivers` by finding ID (`{reason, by}`, `by` the participant). `erc.waive` waives a finding a design has now (or `remove`s a waiver), `erc.configure` sets severities (`default` drops one); both write `erc.json`, deleted when it holds nothing. A waived finding doesn't count; a waiver no design's finding uses is a project-level `waiver_unused`, judged only when every design flattens.
- **`check`.** Loads the project from nothing and reports every file's faults and every design's ERC; `check_failed` (exit 1, the report in `details.report`) on any error a waiver doesn't accept.
- **Testing.** Unit tests per module (file kinds, judging, writes, flattening, every ERC code firing and not, severities and waivers); `tests/cli.rs` scenarios both ways with `RYUEDA_ID_SEED`, among them the sensor breakout (`tests/support/breakout.rs`: a BME280 block, an LDO, pull-ups and a connector, entered by command, its netlist and ERC clean, then a part added, a net renamed and two nets joined, each touching only its files, the join undone and redone through the daemon); `tests/determinism.rs` and `tests/golden/ryueda.txt` (the breakout's and a generated design's netlists and ERC, one thread and eight; in full.yml's `cpu-levels`; `UPDATE_GOLDEN=1 cargo test -p ryueda --test determinism` regenerates it); the `eda` fuzz target (projects from bytes: load, flatten, ERC, the same on one thread and eight).
- **Performance.** `tests/bar.rs` (release only, full.yml): 100 instances of a block of 100 resistors (`tests/support/generated.rs`), 10,000 occurrences and 20,001 nets, load, flatten and ERC from nothing in 28 to 40 ms (bar 1 s), and a write and the next read through a warm daemon, two CLI calls, in 37 to 39 ms (bar 50 ms), on davids-m4 (Apple M4, 10 cores, 16 GB, macOS 26.6.2 25G83); `RYUEDA_BARS=1` asserts the bars as they are, else ten times looser. `cargo bench -p ryueda`: load 5.9 ms, flatten 11 ms, ERC 5.4 ms (medians, same machine).
