## Properties and designator formats (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 1, plan 1.A.

- **Properties.** Named text values (`[a-z_][a-z0-9_]{0,62}`) on the project (`ryueda.json`'s `properties`), a block (`block.json`'s, defaults for every placement of it) and an instance (`instances/<id>.json`'s). A component's `parameters` are its own. A designator format reads them walking out: the component's parameters, then each instance and its block from the innermost occurrence to the root, then the project (`netlist::levels`). Built in and read only: `design`, `block`, `sheet`, `sheets`, `refdes`, `value`, `prefix`, `number`, `rest`, `stack_index`, `stack_letter`, `stack_count`, `stack_path` (`props::BUILT_IN`); a file setting one, or a name that can't be one, is `invalid_document`.
- **Formats.** `props::Template`: text with `{…}` placeholders, each a property or an integer expression in `ryu-doc`'s syntax (`{number + stack_index * 100}`), `{{` and `}}` braces; a byte that doesn't parse is `refdes_format_invalid` with its `position`. Rendering a name no level sets is `property_unknown`; arithmetic on text that isn't an integer, or giving no whole number, `refdes_format_invalid`. The result must be a designator. An occurrence whose formats can't give one has none, and ERC's `refdes_missing` says why (`details.error`).
- **Composition.** Formats apply from the innermost instance outward, each to what the inner levels gave (`refdes`, and `prefix`, `number`, `rest` its parts); an instance's override for an occurrence replaces what its own format would give, and outer formats still apply.
- **Phase 0's rules.** Format 1's `{rule: suffix, value: S}` reads as `{refdes}S` and `{rule: offset, value: N}` as `{prefix}{number + N}{rest}`: exactly the designators phase 0 gave, nested suffixes included (the design wrote `{prefix}{number}S`, which would drop an inner suffix). The CLI's `--suffix` and `--offset` write these formats.
- **Presets.** `suffix_letter` (`{refdes}_{stack_letter}`), `suffix_index` (`{refdes}_{stack_index}`), `offset_hundreds` (`{prefix}{number + stack_index * 100}{rest}`), `prefix_block` (`{block}_{refdes}`); a preset's name is written as its format.
- **Stacks in this plan.** `stack_index` counts an instance among the instances of the same block in the block holding it, in ID order (from 1); `stack_count` is how many; `stack_letter` is `A`, `B`, … `Z`, `AA` (`props::letter`); `stack_path` joins the letters of the stacked levels from the root (`B/C`; a level of one instance adds none). Plan 1.B draws stacks; these built-ins hold already. Choosing instance IDs (`ch_a`, `ch_b`) gives a stable order; random IDs order arbitrarily.
- **Files.** Instances with `properties` or a `refdes` format are instance format 2 (every format is written as text, so any designator format makes the file format 2); blocks with `properties` block format 2; the manifest with `properties` or `schematic` settings manifest format 2 (`conn::format_of`, `Manifest::to_text`). Files that need neither stay at format 1.
- **Sheets.** `schematic.sheet` in the manifest: `size` (`a4` … `a0`, `ansi_a` … `ansi_e`) and `orientation` (`landscape`, `portrait`); A3 landscape by default. A sheet's area is the paper less 10 mm on every side for the PDF's border (`schem::BORDER`).
- **Commands.** `block edit` and `instance edit` take `--property NAME=VALUE` and `--unset-property NAME`; `instance add` and `edit` take `--refdes FORMAT|PRESET`; `project edit` (`project.edit`) takes properties, `--sheet-size` and `--orientation`, guarded by the project's revision.

## The schematic engine (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 2, plan 1.A.

- **Crate.** `ryusch` takes a block as data (`input::Block`: parts with their graphics and pins, nets, the sheet's area, the previous layout, lasting instructions and one-off moves) and gives a layout (`layout::Layout`), notes, the idioms it drew and the nets it labelled for want of room. It depends on `serde` and `serde_json` only (`tests/deps.rs`), reads no files or sessions, and draws child blocks' symbols and the block's port flags itself (`shape::block_symbol`, `shape::port_symbol`). Geometry is integer nanometres, y up, on the 50 mil grid (`geom::GRID`).
- **Text.** Measured by Inter Regular's advance widths (`font::width`), a table generated from `crates/ryueda/fonts/Inter-Regular.ttf` into `crates/ryusch/src/widths.rs` by `UPDATE_WIDTHS=1 cargo test -p ryueda --test font_widths` (which checks it otherwise). A character Inter lacks measures as `0`; kerning is left out, and SVG gives each text its measured width (`textLength`). Designators, values, labels and names are 50 mil; pin numbers 1 mm, the smallest.
- **Order of work.** Instructions resolved (`instr::resolve`); parts kept where the previous layout put them where they still fit and no lasting instruction says otherwise (`engine::keep`); idioms matched and clusters made; what is new placed by flow when nothing is kept, else into free space nearest its neighbours or its idiom's place (`engine::insert`), clear of every part's room and of everything the previous layout drew; `beside`, `near` and `align` applied where they don't hold (`engine::relate`, onto the sheet of the part they name unless a `sheet` instruction names the part's own; parts kept from the previous layout stay put); then each sheet: kept text claimed, kept wires marked, labels and power ports placed (kept ones first: those saying what they said, then renamed ones, then new ones), the remaining nets routed shortest first, and text placed. A net whose routing fails, or which would run longer than a quarter of the sheet's width or cross more than two wires at one connection, takes labels, and the sheet is drawn again; a net the previous layout labelled whose pins are the same keeps its labels. A layout from nothing that breaks a hard rule is made again with its columns spread by 4, 8 and 12 steps.
- **Flow.** Clusters become a graph: driver to sink edges from pin types (output, open collector, tri-state, power out; a port carrying in) and undirected edges otherwise; rails are never edges. Longest-path layers (back edges of a depth-first walk dropped; clusters reached only undirected one layer past their first layered neighbour) give columns; connectors and in-ports take the first, out-ports the last; clusters joined to the rest only by rails go in a band along the top. A cluster whose signal nets reach parts flowed onto another sheet reserves room for a label on each such pin (`Cluster::room_labelled`). Sheets asked for by name are flowed first, and new sheets take the first `Sheet <n>` no sheet has, so nothing else flows onto a named one. Four barycentre sweeps order columns; columns wrap at the sheet's foot; each cluster is nudged down so a pin lines up with one it meets to the left; what runs past the sheet goes to the next (`sheet_full`). Channels are 6 to 16 steps by the nets crossing them.
- **Idioms.** In a fixed order, a part in one at most, parts in key order: crystals with their load capacitors, dividers, feedback resistors (an amplifier's `OUT` to its `-`/`IN-`), decoupling (a capacitor between a supply and ground, given to the active part on that supply with the fewest so far), pull-ups and pull-downs, an LED and its resistor, RC and LC filters, series terminations, connectors (`idiom::find`). Those serving a pin join its part's cluster in canonical shapes: decoupling in a row under the part's pins, supply up; pull-ups standing above, pull-downs hanging below, a column each, five steps out from the pin; a series resistor inline two steps out; a crystal six steps out with its capacitors beyond. Each is moved out along its pin, then down or up, until its room clears every member's (`idiom::clear_of`). The rest are clusters of their own. An `idiom X none` instruction keeps a part out; `idiom X kind` allows it in that kind only; a grouped or oriented part draws no idiom; a part an `edge` instruction holds joins no idiom that serves a part, and none joins it (the cluster would carry it off its edge, or push it from it).
- **Routing.** A sheet's occupancy (`route::Field`): bodies (and the ring round them, which costs), pin lines blocked, pin ends terminals, and the step out of each connected pin kept for its own net; text blocked within half a step; a label (at least a step across both ways) blocks the nodes inside its box, so labels fit on pins two steps apart; every body, text and label box is kept, and a new text or label must overlap none of them exactly. A* over nodes and directions, costs 2 a step, 7 a bend, 14 a crossing, 1 near a body; a wire leaves and enters pins along them, crosses another net only straight through its straight wire, joins only the part of its own net already connected, and never makes a node of four; 400,000 nodes at most a search. Runs are checked whole before marking, and a kept net's runs marked all or none.
- **Labels and power ports.** Supplies point up and ground down from a pin pointing up or down (a stub out and round where it points the other way); on a pin pointing sideways a port points along the pin, since pins sit two steps apart there and a port hanging off one would cover the next. Net labels point along their pin. Candidates: at the pin's end, stubs out to twenty steps, the pin's other ways, then dog-legs; the first whose box is clear and whose stub can be marked is taken. A label with no place is placed again first, the sheet's labels laid again in that order (the fewest left without wins); one still without is a wire to what its net already has on the sheet, else its first candidate. Each label records its text, so a rename is told.
- **Text.** A part's designator and value, two steps apart, at the first free place of: right of the body, above, below, left, then each a step further out, up to 24 steps (`text::candidates`); every anchor on the grid.
- **Hard rules** (`rules::check`, from the layout's geometry alone): grid (placements, pin ends of grid-pinned symbols, labels, text, wire points); `overlap` (parts' extents, texts and labels against each other, and texts and labels against what parts draw, their bodies and pin lines; wires through texts and labels); `spacing` (parts' extents half a step apart); `junction` (no node where four wires of a net meet); `through` (no wire through a body or across a pin's line); `orthogonal`; `inside` (everything inside its sheet's area); `connected` (every pin on a net drawn joined to it, by a wire or a label of its own). Text is upright by construction.
- **Lint** (`lint::lint`), stable codes with a sheet and what they name: `sch_crossings`, `sch_bends` (more than three past the fewest), `sch_long_wire` (a run past a quarter of the width), `sch_label_where_wire` (labels of a net spanning under 12 steps), `sch_wire_where_label` (wires past a fifth of the width, or crossing more than four others), `sch_density` (ink past 300 per mille), `sch_flow_reversed` (a driver more than four steps right of what it drives, with no `flow` instruction), `sch_pin_off_grid`, `sch_idiom_missed` (an idiom's part more than 16 steps from the part it serves). A sheet's score is 100 less: 2 a crossing, 1 an extra bend, 4 a long wire, 2 each label-where-wire and wire-where-label, a point per 10 per mille of density past the threshold, 3 a reversed signal, 1 an off-grid symbol, 3 a missed idiom.
- **Instructions** (`layout::Instruction`, by `op`): `sheet`, `beside`, `near` (a part or `<key>/<pin>`), `align`, `group`, `edge`, `orient`, `net` (`wire`, `label`, `port`), `idiom`, `flow`. A subject naming nothing is `instruction_unresolved` (a note; the instruction is kept). Refusals: `instruction_conflict` for two saying different things of a part's sheet, orientation, place (`edge`, `beside` and `near` are one place), style or idiom, or a part in two groups; `layout_rule` for a turn that isn't a quarter, a part beside or near itself, or power ports on a signal. A part an instruction places elsewhere than the previous layout has is laid out again, unless the previous layout was made with that instruction already (trying again from another start would move it on every edit); a move's parts are held (`held`) and kept from then on.
- **Describe** (`describe::describe`): each sheet's parts with their neighbours by side (within 40 steps), idiom and what it serves, the parts in their row and column; nets drawn as wires, labels or ports, and why a net took labels; instructions with whether each holds (`instr::achieved`); idioms with their notes; lint and scores.
- **SVG** (`svg::draw`, `draw_fit`): exact decimal millimetres; one fixed look (symbols dark red on cream, wires green, labels blue, ports red); sheets side by side on a grey canvas, each its name above it; `draw_fit` crops to what is drawn.
- **Testing.** Unit tests per module; `tests/layout_props.rs` (release only, its own step in full.yml): 64 seeded blocks, each of seven edits (a part added, removed, revalued; a net renamed, joined, split; a pin moved) laid out over the previous layout changes nothing but what it names and the nets on its pins, and every hard rule holds; `tests/determinism.rs` and `tests/golden/layout.txt` (cpu-levels; `UPDATE_GOLDEN=1 cargo test -p ryusch --test determinism`); `cargo bench -p ryusch`; the `schematic` fuzz target (`testing::check_bytes`, its finds replayed in `tests/fuzz_regressions.rs`; in fuzz.yml: a seeded block and up to four instructions and moves from bytes, each a typed refusal or a layout keeping every hard rule, the same twice, and after one value changes over it every other part where it was). Measured on davids-m4 (Apple M4, 10 cores, 16 GB, macOS 26.6.2 25G83), release: a seeded block of 434 parts laid out from nothing in 51 ms over 8 sheets and again after one value changed in 19.5 ms, three runs alike, with other sessions on the machine (load average about 5) (design target: 100 ms for 500 components).

## Schematics in ryueda (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 3, plan 1.A.

- **Layout files.** `blocks/<id>/layout.json` (kind `ryueda.layout`, format 1) holds ryusch's `Layout`: sheets, lasting instructions (`i1`, `i2`, … one past the largest), placements by part key (`<component>`, `<component>:<unit>`, `instance:<id>`, `port:<id>`), labels by net key (`<net>`, `rail:<id>`, `port:<id>`), text and routes. It is part of its block's folder and revision, and is written only by `layout`, `place` and connectivity writes. One that doesn't read, or breaks a hard rule other than `connected`, is `layout_invalid`: laid out again from nothing in memory. One its connectivity has moved past (laying out over it changes it) is stale: laid out in memory, written only by `layout`.
- **Blocks for ryusch** (`schem::build`). Each component's symbol unit is a part (`<component>` for a symbol of one unit, else `<component>:<unit>`, drawn `U1A`, `U1B`); pins every unit has go on the unit with the power pins, else the first. Pin names `~`, empty, equal to the number or KiCad's `Pin_<n>` aren't drawn; numbers are drawn on symbols of more than two pins. A component whose library component or symbol doesn't resolve is drawn as a box with its pins. Child instances are block symbols (inputs, bidirectional and passive ports left, outputs right, power on top), the instance's ID as their second line; the block's ports are flags. Nets: the block's, then the rails its pins and instances use, then its ports. A rail is ground when its voltage is 0 V or its name is `GND`, `VSS`, `AGND`, `DGND`, `PGND`, `0V` (or one of them and `_…`).
- **Writes keep layouts current.** Every connectivity write (`write::commit`) lays out again, over its file, each laid out block whose built input (parts, pins, nets, paper) the write changes, and writes it in the same logged change (`schemcmd::keep_current`). A block never laid out isn't laid out by a write.
- **The agent's vocabulary** (`vocab`): parts by designator (`U3`), unit (`U3:2`), instance (`instance:<id>` or its ID), port (`port:SDA`), or component ID; pins `U3.VDD` (by name, when one pin has it) or `U3.4`; nets by name or ID, `rail:<name>`, `port:<name>`. Instructions are text: `sheet X... S`, `beside X... Y left|right|above|below`, `near X... P`, `align X... row|column`, `group X...`, `edge X... left|right|top|bottom`, `orient X... 0|90|180|270 [mirror]`, `net N wire|label|port`, `idiom X... KIND|none`, `flow X... reversed`, `release X...`; double quotes hold spaces. Listings write them back the same way.
- **Requests.** `layout` (`ryueda layout [--design D] [--block B] [--relayout B[/S]] [--dry-run] [--expect REV]`): lays out a design's blocks (or one) over their files and writes those that change; the block's revision guards one block, the project's a design. `layout.place` (`ryueda place B "instruction"... [--move "instruction"]... [--dry-run] [--expect REV]`): one batch, all or nothing; repeating an instruction changes nothing; `release` drops every lasting instruction naming its subjects; a dry run answers the description. A refusal carries `details.instructions` and `details.fixes`: batches that would hold (release the old instruction then send the new one; the batch without the refused one; `net N label` for ports on a signal). `layout.instructions` (`place B --list`). `describe` (`ryueda describe [--design D] [--block B] [--sheet S]`). `render` (`ryueda render [--design D] [--block B] [--sheet S] [--format svg|png] [--scale PX_PER_MM] [--fit] --out FILE`): SVG, or PNG by resvg with the bundled Inter only (no system fonts; 4 pixels per millimetre by default, 0.5 to 40), the bytes after the answer, the CLI writing `--out` atomically.
- **Check.** `check` adds `schematic`: for each laid out block, `layout_invalid` and `layout_stale` warnings and its lint as warnings. Lint never fails a check in this stage.
- **Fonts.** `crates/ryueda/fonts/Inter-Regular.ttf` (Inter 4.1, static Regular, OFL 1.1, `Inter-LICENSE.txt` beside it, `LICENSES.md` naming the archive and both files' SHA-256): committed, never fetched by a build.
- **Dependencies.** `resvg` 0.49 (Apache-2.0 OR MIT; its rasterizer `tiny-skia` BSD-3-Clause) with `default-features = false, features = ["text"]`, in `ryueda` only.
- **The corpus.** `tests/support/breakout.rs` (the sensor breakout, its symbols drawn as symbols) and `tests/support/rp2040.rs` (an RP2040 board following CIRCUITSTATE's Mitayi-Pico-D1, MIT, commit 8411224b: 53 parts, 228 connections, the RP2040 drawn as three units; generated once from the reference's netlist, maintained as code), over `tests/support/draw.rs` (our own drawings). `tests/schematic_corpus.rs`: every circuit entered by its script, laid out from nothing alike on one thread and eight, every hard rule held, renders into `target/ryueda-look`; and scripted edits (a value, a rename, a part added and connected, a pin moved, a part deleted) changing nothing else. Golden: the `schematic.*` lines of `tests/golden/ryueda.txt` (each block's layout file, SVG and description).
- **Limits.** The engine is plan 1.A's: its layouts keep the hard rules but the RP2040 board takes two A3 sheets, most of its signals as labels; how readable that is is the agent rounds' question (plans 1.C and 1.D). Multi-sheet canvases are a row of sheets in creation order; stacks, drilling in, the layout merge and the PDF are plan 1.B's. Footprints aren't given to the RP2040 board's library components, so its ERC reports `footprint_missing`.
