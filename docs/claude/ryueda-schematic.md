## Properties and designator formats (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 1, plan 1.A.

- **Properties.** Named text values (`[a-z_][a-z0-9_]{0,62}`) on the project (`ryueda.json`'s `properties`), a block (`block.json`'s, defaults for every placement of it) and an instance (`instances/<id>.json`'s). A component's `parameters` are its own. A designator format reads them walking out: the component's parameters, then each instance and its block from the innermost occurrence to the root, then the project (`netlist::levels`). Built in and read only: `design`, `block`, `sheet`, `sheets`, `refdes`, `value`, `prefix`, `number`, `rest`, `stack_index`, `stack_letter`, `stack_count`, `stack_path` (`props::BUILT_IN`); a file setting one, or a name that can't be one, is `invalid_document`.
- **Formats.** `props::Template`: text with `{…}` placeholders, each a property or an integer expression in `ryu-doc`'s syntax (`{number + stack_index * 100}`), `{{` and `}}` braces; a byte that doesn't parse is `refdes_format_invalid` with its `position`. Rendering a name no level sets is `property_unknown`; arithmetic on text that isn't an integer, or giving no whole number, `refdes_format_invalid`. The result must be a designator. An occurrence whose formats can't give one has none, and ERC's `refdes_missing` says why (`details.error`).
- **Composition.** Formats apply from the innermost instance outward, each to what the inner levels gave (`refdes`, and `prefix`, `number`, `rest` its parts); an instance's override for an occurrence replaces what its own format would give, and outer formats still apply.
- **Phase 0's rules.** Format 1's `{rule: suffix, value: S}` reads as `{refdes}S` and `{rule: offset, value: N}` as `{prefix}{number + N}{rest}`: exactly the designators phase 0 gave, nested suffixes included (the design wrote `{prefix}{number}S`, which would drop an inner suffix). The CLI's `--suffix` and `--offset` write these formats.
- **Presets.** `suffix_letter` (`{refdes}_{stack_letter}`), `suffix_index` (`{refdes}_{stack_index}`), `offset_hundreds` (`{prefix}{number + stack_index * 100}{rest}`), `prefix_block` (`{block}_{refdes}`); a preset's name is written as its format.
- **Stacks in this plan.** `stack_index` counts an instance among the instances of the same block in the block holding it, in ID order (from 1); `stack_count` is how many; `stack_letter` is `A`, `B`, … `Z`, `AA` (`props::letter`); `stack_path` joins the letters of the stacked levels from the root (`B/C`; a level of one instance adds none). Plan 1.B draws stacks; these built-ins hold already. Choosing instance IDs (`ch_a`, `ch_b`) gives a stable order; random IDs order arbitrarily.
- **Files.** Instances with `properties` or a `refdes` format are instance format 2 (every format is written as text, so any designator format makes the file format 2); blocks with `properties` block format 2; the manifest with `properties` or `schematic` settings manifest format 2 (`conn::format_of`, `Manifest::to_text`). Files that need neither stay at format 1.
- **Sheets.** `schematic.sheet` in the manifest: `size` (`a4` … `a0`, `ansi_a` … `ansi_e`) and `orientation` (`landscape`, `portrait`); A3 landscape by default. A sheet's area is the paper less 10 mm on every side for the PDF's border (`schem::BORDER`).
- **Commands.** `block edit` and `instance edit` take `--property NAME=VALUE` and `--unset-property NAME`; `instance add` and `edit` take `--refdes FORMAT|PRESET`; `project edit` (`project.edit`) takes properties, `--sheet-size` and `--orientation`, guarded by the project's revision.

## The schematic engine (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 2, plan 1.A.

- **Crate.** `ryusch` takes a block as data (`input::Block`: parts with their graphics and pins, nets, the sheet's area, the previous layout, lasting instructions and one-off moves) and gives a layout (`layout::Layout`), notes, the idioms it drew and the nets it labelled for want of room. It depends on `serde` and `serde_json` only (`tests/deps.rs`), reads no files or sessions, and draws child blocks' symbols and the block's port flags itself (`shape::block_symbol`, `shape::port_symbol`). Geometry is integer nanometres, y up, on the 50 mil grid (`geom::GRID`).
- **Text.** Measured by Inter Regular's advance widths (`font::width`), a table generated from `crates/ryueda/fonts/Inter-Regular.ttf` into `crates/ryusch/src/widths.rs` by `UPDATE_WIDTHS=1 cargo test -p ryueda --test font_widths` (which checks it otherwise). A character Inter lacks measures as `0`; kerning is left out, and SVG gives each text its measured width (`textLength`). Designators, values, labels and names are 50 mil; pin numbers 1 mm, the smallest.
- **Order of work.** Instructions resolved (`instr::resolve`); parts kept where the previous layout put them where they still fit and no lasting instruction says otherwise (`engine::keep`); idioms matched and clusters made; what is new placed by flow when nothing is kept, else into free space nearest its neighbours or its idiom's place (`engine::insert`), clear of every part's room and of everything the previous layout drew; `beside`, `near` and `align` applied where they don't hold (`engine::relate`, onto the sheet of the part they name unless a `sheet` instruction names the part's own; parts kept from the previous layout stay put); then each sheet: kept text claimed, kept wires marked, labels and power ports placed (kept ones first: those saying what they said, then renamed ones, then new ones), the remaining nets routed shortest first, and text placed. A net whose routing fails, or which would run longer than a quarter of the sheet's width or cross more than two wires at one connection, takes labels, and the sheet is drawn again; a net the previous layout labelled whose pins are the same keeps its labels. A layout from nothing that breaks a hard rule is made again with its columns spread by 4, 8 and 12 steps.
- **Flow.** Clusters become a graph: driver to sink edges from pin types (output, open collector, tri-state, power out; a port carrying in) and undirected edges otherwise; rails are never edges. Longest-path layers (back edges of a depth-first walk dropped; clusters reached only undirected one layer past their first layered neighbour) give columns; connectors and in-ports take the first, out-ports the last; clusters joined to the rest only by rails go in a band along the top. A cluster whose signal nets reach parts flowed onto another sheet reserves room for a label on each such pin (`Cluster::room_labelled`). Sheets asked for by name are flowed first, and new sheets take the first `Sheet <n>` no sheet has, so nothing else flows onto a named one. Four barycentre sweeps order columns; columns wrap at the sheet's foot; each cluster is nudged down so a pin lines up with one it meets to the left (a pin pointing up two steps under it, met from above with one bend), and a port's flag alone in its column moves up or down onto the line of the pin it meets in the nearest other column (a step to four past the end of one pointing up or down) where its room is free, up to the sheet's margin, sliding along its line towards the pin (3, 6 or 9 steps, flags staggered) where its own place in the column is too close to another flag's (since 1.B's review: a straight wire, no jog), every flag tried twice so one another held can follow; what runs past the sheet goes to the next (`sheet_full`). Channels are 6 to 16 steps by the nets crossing them.
- **Idioms.** In a fixed order, a part in one at most, parts in key order: buck converters and op-amp stages first (since 1.C, see Agent round 1), crystals with their load capacitors, dividers, feedback resistors (an amplifier's `OUT` to its `-`/`IN-`), decoupling (a capacitor between a supply and ground, given to the active part on that supply with the fewest so far, and to that part's pin on the supply with the fewest), pull-ups and pull-downs, an LED and its resistor, RC and LC filters, series terminations, connectors (`idiom::find`). Those serving a pin join its part's cluster in canonical shapes: decoupling on the line out of the pin it serves (since 1.B's review: standing two steps under it, three steps out and three more for each further capacitor on the pin; from a pin pointing up or down, beside the part past its body), supply up; pull-ups standing above, pull-downs hanging below, a column each, five steps out from the pin; a series resistor inline two steps out; a crystal six steps out with its capacitors beyond. Each is moved out along its pin, then down or up, until its room clears every member's (`idiom::clear_of`). The rest are clusters of their own. An `idiom X none` instruction keeps a part out; `idiom X kind` allows it in that kind only; a grouped or oriented part draws no idiom; a part an `edge` instruction holds joins no idiom that serves a part, and none joins it (the cluster would carry it off its edge, or push it from it).
- **Routing.** A sheet's occupancy (`route::Field`): bodies (and the ring round them, which costs), pin lines blocked, pin ends terminals, and the step out of each connected pin kept for its own net; text blocked within half a step; a label (at least a step across both ways) blocks the nodes inside its box, so labels fit on pins two steps apart; every body, text and label box is kept, and a new text or label must overlap none of them exactly. A* over nodes and directions, costs 2 a step, 7 a bend, 14 a crossing, 1 near a body; a wire leaves and enters pins along them, crosses another net only straight through its straight wire, joins only the part of its own net already connected, and never makes a node of four; 400,000 nodes at most a search. Runs are checked whole before marking, and a kept net's runs marked all or none.
- **Labels and power ports.** Supplies point up and ground down from any pin (`label::upright`): from a pin pointing sideways, a stub of two steps or more and then up or down; from one pointing the other way, out a step, across and round. Net labels read across the page: along a pin pointing sideways, out of a stub from one pointing up or down (to the right first). A net label is a name on its wire (a line as long as the name, the name a quarter step above it), with no outline, so it can't be taken for a port's flag, which leaves the sheet; a port's flag names its net, so its pin takes no label. Order: labels keeping their place, renamed ones, new ones; within each, net labels before ports, ground from the lowest pin up and supplies from the highest down, so each port turns off its pin clear of those placed before it. A rail's pin within four steps of its rail's wires or ports joins them by a wire first (a part's row of supply pins draws a comb with one port). Then candidates (`label::candidates`: straight out, or round); then a wire to what its net has on the sheet (a rail's only within ten steps); then detours (`label::detours`: the pin's other ways, dog-legs); last the pin's own way, as labels once all went (`label::sideways`). A label with no place is placed again first, the sheet's labels laid again in that order (the fewest left without wins); one still without goes at its pin's end, along the pin. Each label records its text, so a rename is told. A previous label on a run from its pin through it (a bypass capacitor's, the capacitor deleted) keeps its place, the run cut there; a port's flag isn't counted among a labelled net's pins when the labels are kept.
- **Bypass capacitors** (since 1.B's review). A decoupling capacitor and the pin it serves are joined by a wire, before any other label is placed, and their rail's one port sits on that wire: where the previous layout had it, else at its first bend, else nearest its middle, pointing up, never where the wire goes on up. A pin's further capacitors join that wire (their previous wires kept while they still reach it). New bypass wires go round every label the previous layout drew on the sheet, so an edit pushes none from its place. With nowhere for the port, or no route, both pins take ports as any others. A part of two pins standing up with ground on top or a supply below is turned over by default (`engine::default_turn`), so its ground points down and its supply up straight off their pins.
- **Text.** A part's designator and value, two steps apart, at the first free place of: right of the body, above, below, left, then each a step further out, up to 24 steps (`text::candidates`); every anchor on the grid.
- **Hard rules** (`rules::check`, from the layout's geometry alone): grid (placements, pin ends of grid-pinned symbols, labels, text, wire points); `overlap` (parts' extents, texts and labels against each other, and texts and labels against what parts draw, their bodies and pin lines; wires through texts and labels); `spacing` (parts' extents half a step apart); `junction` (no node where four wires of a net meet); `through` (no wire through a body or across a pin's line); `orthogonal`; `inside` (everything inside its sheet's area); `connected` (every pin on a net drawn joined to it, by a wire or a label of its own). Text is upright by construction.
- **Lint** (`lint::lint`), stable codes with a sheet and what they name: `sch_crossings`, `sch_bends` (more than three past the fewest), `sch_long_wire` (a run past a quarter of the width), `sch_label_where_wire` (labels of a net spanning under 12 steps), `sch_wire_where_label` (wires past a fifth of the width, or crossing more than four others), `sch_density` (ink past 300 per mille), `sch_flow_reversed` (a driver more than four steps right of what it drives, with no `flow` instruction), `sch_pin_off_grid`, `sch_idiom_missed` (an idiom's part more than 16 steps from the part it serves; a bypass capacitor wired on its pin's line never is), and since 1.B's review `sch_power_sideways` and `sch_ground_sideways` (a supply not pointing up, ground not down), `sch_label_vertical` (a net label or a port reading up or down the page), `sch_jog` (a wire stepping aside and carrying on the way it went: each Z of two turns; it names the parts it steps round, `topology::jog_obstacles`, and round a pin's bypass capacitors the standard fix: `BUCK-EN jogs under VIN's bypass caps (C1, C2, C3). Standard buck input: the caps stand on the input wire beside VIN, and BUCK-EN is taken off before them.`) and `sch_bypass_apart` (a decoupling capacitor not wired to the pin it serves); since round 2, `sch_pin_name_outside` (a pin's name past its body or into another's), `sch_port_bent` (a port's flag whose wire turns), `sch_floating` (a part whose signal pins all reach their nets by labels though one of those nets has another pin on its sheet; ports and connectors aren't judged), and since the owner's scope decision of 2026-11-02 `sch_resistor_style` (a resistor in the style the project doesn't prefer), `sch_out_of_line` (a part whose body's middle, or a two-pin part's pin axis, lines up with no other part's), `sch_bank_not_in_row` (parts of one prefix between the same nets not in one row or column) and `sch_topology` (a recognised circuit out of its standard shape, see Topologies). A rail's wires are never `sch_wire_where_label` (a rail is drawn by ports; its wires are bypass and local ties). Each finding costs its rule's weight per unit (`lint::RULES`: 2 a crossing, 1 an extra bend, 4 a long wire, 2 each label-where-wire and wire-where-label, 1 per 10 per mille of density past the threshold, 3 a reversed signal, 1 an off-grid symbol, 3 a missed idiom, 3 a sideways supply or ground, 15 a vertical label or port, 2 a jog, 3 a bypass capacitor apart, 3 a name past its body, 3 a bent port, 8 a floating part, 1 a resistor's style, 2 a part out of line, 3 a bank out of its row, 10 a topology out of shape); a sheet's score is 100 less their sum. Findings carry `points`, `severity` and the `prefs` that drove them, and since 1.D `fixes`: batches of instructions ready to send (`Finding::fixes`, written as text by ryueda) for flipped, floating and out-of-line parts, labels and wires, banks, reversed flow and topologies. Each rule is a `lint::Rule` in `lint::RULES` (code, weight, unit, `what`, `why`, `fix` and `evidence`, the last only measured facts, round findings and drafting conventions), which `ryueda lint --explain CODE` answers with the weight and severity now.
- **Lint preferences** (`lint::Prefs`, `lint_with`; `lint` is it with the defaults): `weights` and `severity` (`off`, `warning`, `error`; `off` drops a rule's findings and says so in the sheet's `notes`) by rule, and `prefer`: `resistor` (`us`, the zigzag, by default, or `iec`, the box; read from a part's graphics, `lint::resistor_style`) and `local_nets` (`wires` by default; `labels` turns `sch_floating` and `sch_label_where_wire` off). A finding a preference drove says which in its message (`(prefer.resistor = iec)`, `(weights.sch_jog = 5)`), so an agent reading only the lint knows what to change: the drawing, or the preference.
- **Topologies** (`ryusch::topology`, `judge`). A buck converter is an active part's switch pin (SW, LX, PH), the inductor on that net, its catch diode if any, capacitors to ground on the inductor's far net (the output), and capacitors to ground on the part's input pin (VIN, PVIN, VCC, IN). Its standard drawing: the inductor across the page with the switch pin wired straight to its left end, the diode standing below the switch node to ground, the output capacitors on the inductor's right end, the input capacitors on the input wire beside VIN with any pin tied to the input taken off before them, every part wired. An op-amp stage is an active part's output and inverting input (`-`, `IN-`, `INN`), the resistors and capacitors between them (feedback) and those from a signal into the inverting input (input). Its standard drawing: the feedback elements across the page above the amplifier, wired OUT to IN-, the input element across the page left of IN-, wired. Each judged circuit lists what breaks the shape (`L1 stands upright`, `D1 is joined to the switch node by a label`); `sch_topology`'s message names the circuit, those problems and the standard drawing. The engine's placement of these shapes, of clean rows and of wired local circuits is 1.C/1.D's (requirements 54, 55 and 56).
- **Instructions** (`layout::Instruction`, by `op`): `sheet`, `beside`, `near` (a part or `<key>/<pin>`), `align`, `group`, `edge`, `orient`, `net` (`wire`, `label`, `port`), `idiom`, `flow`. A subject naming nothing is `instruction_unresolved` (a note; the instruction is kept). Refusals: `instruction_conflict` for two saying different things of a part's sheet, orientation, place (`edge`, `beside` and `near` are one place), style or idiom, or a part in two groups; `layout_rule` for a turn that isn't a quarter, a part beside or near itself, or power ports on a signal. A part an instruction places elsewhere than the previous layout has is laid out again, unless the previous layout was made with that instruction already (trying again from another start would move it on every edit); a move's parts are held (`held`) and kept from then on.
- **Describe** (`describe::describe`): each sheet's parts with their neighbours by side (within 40 steps), idiom and what it serves, the parts in their row and column; nets drawn as wires, labels or ports, and why a net took labels; instructions with whether each holds (`instr::achieved`); idioms with their notes; lint and scores.
- **SVG** (`svg::draw`, `draw_fit`): exact decimal millimetres; one fixed look (symbols dark red on cream, wires green, net labels' names blue on their green line, ports red); sheets side by side on a grey canvas, each its name above it; `draw_fit` crops to what is drawn.
- **Testing.** Unit tests per module; `tests/layout_props.rs` (release only, its own step in full.yml): 64 seeded blocks, each of seven edits (a part added, removed, revalued; a net renamed, joined, split; a pin moved) laid out over the previous layout changes nothing but what it names and the nets on its pins, and every hard rule holds; `tests/determinism.rs` and `tests/golden/layout.txt` (cpu-levels; `UPDATE_GOLDEN=1 cargo test -p ryusch --test determinism`); `cargo bench -p ryusch`; the `schematic` fuzz target (`testing::check_bytes`, its finds replayed in `tests/fuzz_regressions.rs`; in fuzz.yml: a seeded block and up to four instructions and moves from bytes, each a typed refusal or a layout keeping every hard rule, the same twice, and after one value changes over it every other part where it was). Measured on davids-m4 (Apple M4, 10 cores, 16 GB, macOS 26.6.2 25G83), release: a seeded block of 434 parts laid out from nothing in 51 ms over 8 sheets and again after one value changed in 19.5 ms, three runs alike, with other sessions on the machine (load average about 5) (design target: 100 ms for 500 components).

## Schematics in ryueda (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 3, plan 1.A.

- **Layout files.** `blocks/<id>/layout.json` (kind `ryueda.layout`, format 1) holds ryusch's `Layout`: sheets, lasting instructions (`i1`, `i2`, … one past the largest), placements by part key (`<component>`, `<component>:<unit>`, `instance:<id>`, `port:<id>`), labels by net key (`<net>`, `rail:<id>`, `port:<id>`), text and routes. It is part of its block's folder and revision, and is written only by `layout`, `place` and connectivity writes. One that doesn't read, or breaks a hard rule other than `connected`, is `layout_invalid`: laid out again from nothing in memory. One its connectivity has moved past (laying out over it changes it) is stale: laid out in memory, written only by `layout`.
- **Blocks for ryusch** (`schem::build`). Each component's symbol unit is a part (`<component>` for a symbol of one unit, else `<component>:<unit>`, drawn `U1A`, `U1B`); pins every unit has go on the unit with the power pins, else the first. Pin names `~`, empty, equal to the number or KiCad's `Pin_<n>` aren't drawn; numbers are drawn on symbols of more than two pins. A component whose library component or symbol doesn't resolve is drawn as a box with its pins. Child instances are block symbols (inputs, bidirectional and passive ports left, outputs right, power on top), the instance's ID as their second line; the block's ports are flags. Nets: the block's, then the rails its pins and instances use, then its ports. A rail is ground when its voltage is 0 V or its name is `GND`, `VSS`, `AGND`, `DGND`, `PGND`, `0V` (or one of them and `_…`).
- **Writes keep layouts current.** Every connectivity write (`write::commit`) lays out again, over its file, each laid out block whose built input (parts, pins, nets, paper) the write changes, and writes it in the same logged change (`schemcmd::keep_current`). A block never laid out isn't laid out by a write.
- **The agent's vocabulary** (`vocab`): parts by designator (`U3`), unit (`U3:2`), instance (`instance:<id>` or its ID), port (`port:SDA`), or component ID; pins `U3.VDD` (by name, when one pin has it) or `U3.4`; nets by name or ID, `rail:<name>`, `port:<name>`. Instructions are text: `sheet X... S`, `beside X... Y left|right|above|below`, `near X... P`, `align X... row|column`, `group X...`, `edge X... left|right|top|bottom`, `orient X... 0|90|180|270 [mirror]`, `net N wire|label|port`, `idiom X... KIND|none`, `flow X... reversed`, `release X...`; double quotes hold spaces. Listings write them back the same way.
- **Requests.** `layout` (`ryueda layout [--design D] [--block B] [--relayout B[/S]] [--dry-run] [--expect REV]`): lays out a design's blocks (or one) over their files and writes those that change; the block's revision guards one block, the project's a design. `layout.place` (`ryueda place B "instruction"... [--move "instruction"]... [--dry-run] [--expect REV]`): one batch, all or nothing; repeating an instruction changes nothing; `release` drops every lasting instruction naming its subjects; a dry run answers the description. A refusal carries `details.instructions` and `details.fixes`: batches that would hold (release the old instruction then send the new one; the batch without the refused one; `net N label` for ports on a signal). `layout.instructions` (`place B --list`). `describe` (`ryueda describe [--design D] [--block B] [--sheet S]`). `render` (`ryueda render [--design D] [--block B] [--sheet S] [--format svg|png] [--scale PX_PER_MM] [--fit] --out FILE`): SVG, or PNG by resvg with the bundled Inter only (no system fonts; 4 pixels per millimetre by default, 0.5 to 40), the bytes after the answer, the CLI writing `--out` atomically.
- **Check.** `check` adds `schematic`: for each laid out block, `layout_invalid` and `layout_stale` warnings and its lint, at each rule's severity (warnings unless `lint.json` makes a rule an error, which fails the check).
- **Lint preferences** (`ryueda::lint`, since 1.B's review). `lint.json` beside the manifest (kind `ryueda.lint`, format 1, as `erc.json`) holds `ryusch::lint::Prefs`: weights and severities naming rules (else `invalid_document` at the pointer; a weight is 0 or more) and `prefer`. It is a project file in the project's revision (hashed only when present, so other projects' revisions didn't move). `lint.get` (`ryueda lint`: the preferences, every rule with its default weight and unit, the revision) and `lint.configure` (`ryueda lint configure --weight CODE=N --severity CODE=LEVEL --prefer resistor=us|iec --prefer local_nets=wires|labels`, `default` for a value putting it back; one logged change guarded by the project's revision, the file deleted when it holds nothing). `describe`, `layout`, `place` and `check` lint under it.
- **Fonts.** `crates/ryueda/fonts/Inter-Regular.ttf` (Inter 4.1, static Regular, OFL 1.1, `Inter-LICENSE.txt` beside it, `LICENSES.md` naming the archive and both files' SHA-256): committed, never fetched by a build.
- **Dependencies.** `resvg` 0.49 (Apache-2.0 OR MIT; its rasterizer `tiny-skia` BSD-3-Clause) with `default-features = false, features = ["text"]`, in `ryueda` only.
- **The corpus.** `tests/support/breakout.rs` (the sensor breakout, its symbols drawn as symbols) and `tests/support/rp2040.rs` (an RP2040 board following CIRCUITSTATE's Mitayi-Pico-D1, MIT, commit 8411224b: 53 parts, 228 connections, the RP2040 drawn as three units; generated once from the reference's netlist, maintained as code), over `tests/support/draw.rs` (our own drawings; resistors the US zigzag by default since 1.B's review, the IEC box `draw::resistor_box` allowed; capacitors 3 mm wide, with `C_Small`-like small versions the breakout draws; an IC's box sized by `draw::sides` until every pin's name fits inside it; the jumper's and crystal's pin names hidden as KiCad hides them). `tests/schematic_corpus.rs`: every circuit entered by its script, laid out from nothing alike on one thread and eight, every hard rule held, renders into `target/ryueda-look`; and scripted edits (a value, a rename, a part added and connected, a pin moved, a part deleted) changing nothing else. Golden: the `schematic.*` lines of `tests/golden/ryueda.txt` (each block's layout file, SVG and description).
- **Limits.** The engine is plan 1.A's: its layouts keep the hard rules but the RP2040 board takes two A3 sheets, most of its signals as labels; how readable that is is the agent rounds' question (plans 1.C and 1.D). Multi-sheet canvases are a row of sheets in creation order; stacks, drilling in, the layout merge and the PDF are plan 1.B's. Footprints aren't given to the RP2040 board's library components, so its ERC reports `footprint_missing`.

## The canvas, stacks, the layout merge and the PDF (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; these are its phases 4 to 6, plan 1.B.

- **The canvas** (`ryusch::canvas`). A block's sheets are arranged as a block diagram reads: power sheets (one that gives a supply, a power output pin or a power port, and at least half of whose parts belong to the supply) in a row above; the rest in columns by the longest path of the signals between sheets (a pin that drives a signal, or a port carrying one in, on one sheet, a pin that takes it, or a port carrying it out, on another; edges closing a cycle left out by a depth-first walk in sheet ID order), a column's sheets one under another, `canvas::GAP` (10 steps) apart. A sheet the previous layout placed keeps its place unless the kept sheets would now overlap (the paper changed), which lays the canvas out again; a new sheet takes its place by flow, else the free place on the canvas's grid of sheets nearest it. `canvas::order` is the top row first, each row left to right: the order `describe` gives (`canvas`, and each sheet's `canvas_mm`) and the PDF pages by.
- **Stacks** (`ryusch::shape::stack_symbol`). A stack is one block symbol: up to two copies (`STACK_DRAWN`) behind the front one, each `STACK_STEP` (half a step) down and to the right, filled, and a badge `×n` in the body's top right; its right pins reach past the copies (their ends on the grid, their length the overhang rounded up to a step plus two). A port pin carries each layer's net (`Pin::layers`, behind the front's `net`): where the layers' nets differ (`Pin::stacked`), every net it is on takes labels, and the pin takes one label naming each layer's net, in layer order, each once (`Block::label_text`: `IN_A, IN_B`); the `connected` rule holds a stacked pin to that label. Labels keep what they say (`Label::text`), which rules, lint, SVG and the merge read. A plain block symbol is a stack of one, bit for bit.
- **Stacks in ryueda** (`schem::build`). Instances of one block in one parent whose ports connect alike (each port to the same rail, or left unconnected, in every one, else to some signal) are one stack, its layers in instance ID order (the order `stack_index` counts), keyed by its first instance (`instance:<front>`), its value line the layers' IDs. Instances whose port maps differ in that structure are drawn apart. An instruction naming any layer names the stack (`Built::front`).
- **Layers and drilling in** (`schem::layers`). Every occurrence of a block in the project's designs (designs in ID order, each depth first, instances in ID order) is a layer: its instance path, its stack path (the stacked levels' letters, `A/B`) and each component's designator there. A block is laid out once for all its layers: its text reserves the widest designator any layer gives (by the font's measure), so every layer draws the same. `render --layer <path>` (an instance path or a stack path, `<design>:` before either) draws that layer's designators, else the first's; the answer lists `layers` (the viewer's tabs) and the `layer` drawn, and `describe` the same when there are several.
- **Notifications.** `project.changed`'s revisions name `layout/<block>`, the BLAKE3 (32 hex) of each layout file's canonical text (`null` for one that doesn't read), so a viewer redraws only the blocks whose layout moved.
- **Over a previous layout.** A part one of whose labels found no place where it stands (its label grew: a stack's new layer, a longer name) is placed again, by itself, into free space near its neighbours (`Outcome::crowded`), rather than a hard rule broken. A part an instruction moves (`sheet`, `beside`, a move) brings the idioms serving it, which kept where they were would hold it there. A net's runs are written sorted, so a layout laid out over itself is the same file. A new sheet whose place by flow is taken takes the nearest free one not above it (the row above is the power sheets').
- **The layout merge** (`ryusch::merge`). `merge(block, base, ours, theirs)` with `block` the merged connectivity: keys are sheets, parts' places, parts' text, each label by its net and pin (`<net>|<part>/<pin>`) and each net's wires by sheet (`<net>|<sheet>`); one side's change taken, alike either, both differently a conflict. Instructions merge by what they say: the base's both kept, then ours' additions under ours' IDs, then theirs' under the next free IDs. Conflicts are areas: keys changed differently on both sides, joined with every key of the other side whose boxes overlap on a sheet, joined again while they share an item (a part's place, text and labels are one) or overlap; each `Conflict` lists `areas` by sheet and the keys `ours` and `theirs` changed there. Ours' values stand in the merged layout. `resolve(.., repairs)` settles each conflict by `Ours`, `Theirs` or `Relayout` (its keys back to the base's, its parts' nets' wires and labels and their text dropped) and lays the block out over the result incrementally, so what neither side touched keeps its bits; merged instructions that can't hold are refused as the engine refuses them. The error code `layout_conflict` is ryu-doc's for stage 4's driver and `merge status`, which wrap this unchanged.
- **Paint** (`ryusch::paint`). What a sheet draws as items in its own frame (polylines, circles, arcs through three points, Béziers, text with an anchor), in drawing order, with where each label and block symbol is; SVG draws from it, its bytes unchanged.
- **The PDF** (`ryueda::pdf`, `ryueda::output`). `output` (`ryueda output [<design>] --out FILE [--layers all|first]`) pages a design: each sheet a page at the project's paper, depth first from the root (a block's sheets in canvas order, then the blocks its symbols place, by where the symbols sit: sheet, top to bottom, left to right), a stack's sheets once per layer with that layer's designators (`all`), or once with its layers named (`first`). Each page has a plain border 5 mm in (`pdf::FRAME`) and a heading (`<design> · <block> · sheet n/m <name> · layer <path>`) in the band above the sheet; the sheet's frame sits at the PDF border's margin (`schem::BORDER`). Text is Inter subset (`subsetter`, without variable fonts) and embedded as a CID font, Identity-H, with a ToUnicode map, its widths the font's, so text can be searched and selected; arcs are cubic Béziers by `ryu_math`. Bookmarks follow the hierarchy (a block occurrence, its sheets and its children); a block symbol links to its block's first page; each net label carries `→ n, m`, the other pages its flattened net is labelled on, each number a link. No time stamp or ID: the document's info is its title and `ryueda`, and the font subset's name is derived from its glyphs. Dependencies: `pdf-writer` 0.15, `subsetter` 0.2 (`default-features = false`), `ttf-parser` 0.25 (now a dependency), `miniz_oxide` 0.8 and `ryu-math`.
- **The corpus and its references.** `tests/schematic_corpus/manifest.txt` declares each circuit's reference (`source`, `licence`, `file <path> <sha256>` under `references/`, or `fetch <url> <sha256>`); `tests/schematic_refs.rs` checks it (every committed file declared and its bytes its hash, only under Apache-2.0, MIT, BSD-3-Clause or CC-BY-4.0); `scripts/fetch-schematic-refs.sh` fetches the rest into `target/schematic-refs`. Committed: Mitayi-Pico-D1 (MIT), the TPS54331 buck (MIT), mhd314's output stage (BSD-3-Clause), Olimex's ESP32-PoE M2 (Apache-2.0); fetched: Adafruit's BME280 breakout (CC-BY-SA-3.0). Crossings counted by hand on each reference are plan 1.D's.
- **The corpus.** Five circuits in `tests/support/` (our own symbols, each circuit's connectivity its reference's within the cut its doc comment states): the breakout, the RP2040 board, the buck (`buck.rs`: the TPS54331 and its network, one block of 20 parts), the front end (`frontend.rs`: blocks `ivconv` and `baldiff` each placed twice by `amp`, two stacks of two with the `suffix_letter` format; OPA1612 and OPA1622 as three units each) and the Ethernet PHY (`ethernet.rs`: the LAN8710A's network in `eth`, the RMII pins its ports, and `status_led` placed twice as a stack; the reference's link LED sinks where its activity LED sources, and the stack takes the activity LED's wiring). `tests/schematic_corpus.rs` lays every circuit out keeping every rule, alike on one thread and eight; holds scripted edits on four of them (a value, a rename, a part added and hung on a net, a pin moved, a part deleted: a bypass capacitor's deletion may draw again the capacitors on its pin, which are one drawing), the RP2040's power unit moved to a sheet of its own and the front end's third I/V converter added to its stack, to changing only what they name; and merges scripted branches of the breakout. The `schematic.*` lines of `tests/golden/ryueda.txt` hold every circuit's layout files, SVGs (each stacked layer's too), descriptions and PDF. Measured on davids-m4 (Apple M4, 10 cores, 16 GB, macOS 26.6.2 25G83, release, one thread, in process, load average about 5): each circuit laid out from nothing in 7 to 33 ms and paged into a PDF in 10 to 19 ms (design targets 2 s and 1 s).
- **Limits.** Cross-references are drawn under their labels outside what the layout reserves, so they can touch the drawing below a label (stage 2's formatter reserves room). A stack is keyed by its first instance, so deleting that instance places the stack again. Laying a block out reads its layers, flattening each design that reaches it, on every write that keeps layouts current. The layout merge isn't fuzzed (layout_props' seeded merges and the scripted branches hold it).

## Agent round 1 (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 7, plan 1.C.

- **Recognised circuits as idioms.** `IdiomKind` gains `buck` and `opamp_stage` (13 kinds), matched before every other kind, so their parts never become decoupling, feedback or filter idioms; `idiom X buck` and `idiom X none` work on them as on any kind.
  - A buck's power stage stands around its switch pin (`topology::switch_pin`: `SW`, `LX`, `PH`, `SWITCH`, and `SW` or `LX` numbered or lettered, never a debug port's `SWCLK`, `SWDIO`, `SWO`): the inductor across the page, its switch end four steps out; the catch diode two steps out and two down, cathode up; the output capacitors standing on the inductor's far end, three steps apart, joined to it by the bypass wiring, the rail's port on that wire.
  - An op-amp stage (an active part's output and inverting input, every resistor or capacitor between them, the first one from a signal into the inverting input): feedback elements across the page above the amplifier, one row each; the input element across the page into the inverting input. 1.A's `feedback` idiom stays for amplifiers no stage takes.
  - `topology::judge` runs once a sheet, and a net any input capacitor is on (the input, ground) is never a jog under the input capacitors.
- **Out-port flags beside their drivers.** An out port whose net one part's pin drives (`place::sole_driver`) joins that pin's cluster six steps out on its line when the pin points right; otherwise it is left to the layering (a column past its driver) rather than held to the right edge. So a stage's output is a short wire, not a label.
- **Bypass capacitors.** Decoupling idioms are placed after every other idiom.
  - One part's capacitors on one side of it stand in one row under its lowest decoupled pin there, as stairs: the lowest pin's nearest, each higher pin's further out, so every wire is an L and none crosses another.
  - Slots are as wide as the widest capacitor's room. The row starts past whatever stands out beside the part (its own room, other idioms' parts below the row's line), plus how far a capacitor's text reaches back towards it, so a lower pin's wire is taken off before the capacitors (the buck's EN).
  - On a pin pointing up or down they run along one row per part and side.
  - A capacitor the previous layout wired to some of its rail's users' pins chooses among those alone (`idiom::wired_before`), so deleting or adding another reassigns none.
- **Jumpers beside their pull resistors.** A two-pin connector strapping a pin to the same rail as its pull resistor joins that pull idiom: on the pin's own line past the resistor's room, pins towards the part, the signal pin uppermost (`signal_on_top`, which may mirror). So the pin's wire runs straight into it and the resistor hangs off it, rather than the jumper flowing to the sheet's edge.
- **Layering.** A group of clusters no layered cluster reaches (an IC and its passives, nothing driving it) starts from its most connected cluster, so it flows in columns rather than stacking in one.
- **Local circuits.** A two-pin symbol (not a connector) no idiom took, with a signal net that reaches one active pin and otherwise only parts of two pins or fewer and ports, joins that pin. Where its other end is a rail it stands off the pin as a pull-up or pull-down does (and is named one); otherwise it goes across from it as a series element (`series_termination`). A series element's far net is local to it in turn (a compensation network's C and R).
- **Keeping wires.** A labelled net whose label has no room is wired to its own; that keeps the previous run from the pin to the net's wiring or another of its pins while it can still be marked, before searching. Bypass capacitors are wired in two passes, every kept run first, then new searches.
- **Banks in the lint.** Decoupling capacitors' banks are keyed by the part and side they serve: a bank split across parts asks only that each part's own satellites line up.
- **The corpus from nothing.** `the_corpus_from_nothing_draws_what_the_lint_teaches` enters each circuit by its script and lays every block out again from nothing, as round projects are. Its bars:
  - no `sch_topology`;
  - no `sch_bank_not_in_row`;
  - no `sch_jog` on the buck's EN;
  - `sch_floating` at most 35 over the corpus. This departs from the plan's 20, as the coxswain decided on 2026-11-02. What still floats needs placement across clusters (a TVS beside its connector, clamps beside their ports, parts on nets with several active pins), which is 1.D's requirement (work item 4530).

  The corpus's own layouts are their scripts' history, so 1.D's metric bars should judge layouts from nothing too.
- **The round's kit.** `round_projects` (ignored; `RYUEDA_ROUND_OUT=<dir> cargo test -p ryueda --test schematic_corpus -- --ignored round_projects`) writes each circuit laid out from nothing with no instructions, with `baseline.json` (each block's lint). `scripts/schematic-round/` holds:
  - `ryueda`, a wrapper that logs every call to `ROUND_LOG` and refuses (`round_arm`, exit 2) what the session's arm doesn't allow: `--move` under `ROUND_ARM=lasting`, lasting instructions under `moves`, `render` and any `--render` under `ROUND_SEE=describe` (flags taking a value, `--flag VALUE` or `--flag=VALUE`, never count as instructions; `python3 -I scripts/schematic-round/test-ryueda.py` checks it);
  - `brief.md`, the one task every session gets;
  - `session.sh`, which prepares a session's folder, PATH and environment, with its own daemon;
  - `summarise.py`, which turns a round into a table and `summary.json`.

  Sessions are fresh subagents given only the brief. None of it runs in CI.
- **Round 1.** Twenty sessions (five circuits, lasting instructions or one-off moves, PNG renders or `describe` alone) raised the mean score per sheet most on the rp2040 board and the buck (20 → 51 to 75, 16 → 51 to 63) and hardly at all on the breakout, front end and Ethernet PHY. `describe` alone did as well as PNGs, and moves a little better than lasting instructions. The report is document 332 in the Coxswain planning project, the gallery `cox visual` 01M6F7CK17PQGXGKFZKTFG24A8. The coxswain accepted the revised Task 13 on 2026-11-02 without a review round (coxswain#253).
- **Interface changes.** Task 13 makes these, each answering findings of the report:
  - **`net X wire` acts** (F6 to F8). A net whose style an instruction or move sets is no longer held to the labels a previous layout gave it. It is routed, and where it still takes labels (too long, crossings, no route) the answer's `notes` gives `net_style_not_held` with the reason. A net reaching a stacked pin keeps its instruction but is drawn by labels, with a `net_style_not_held` note, since a stacked pin is drawn by one label per layer. A net's `why` is the layout's own.
  - **Fixes that hold** (F9). `fixes` never offers an empty batch. A conflict inside a batch offers each conflicting instruction alone with the batch's others. A conflict with a lasting net instruction offers `release <id>` and then the batch. A style conflict's message names the net.
  - **No broken writes** (F11). `place` checks `rules::check` on what it would write and refuses a layout breaking a hard rule (`layout_rule`, with `broken` and `fixes`), dry run or not.
  - **`release`** (F9, F10). It takes an instruction ID (`release i7`), a net (`release net:SDA`, or a bare net name that names no part) or a part (every instruction naming it, as before). The answer lists what it dropped. The parts those instructions placed are laid out again (`input::Relayout::Parts`), so a release undoes what it did.
  - **`holds` is geometry** (F1, F2). `instr::judge` measures what the drawing shows, as the lint does:
    - `beside` and `near` hold within `lint::IDIOM_REACH` on the named side;
    - `align` holds on the lint's lines (`lint::part_lines`);
    - `group` holds as one cluster within the reach.

    An instruction that doesn't hold says why in `why` (`R7 is 175 mm from R8; beside means within 20.3 mm`). Listing entries and moves that changed nothing say `unchanged`.
  - **Names as drawn** (F13, F14). `place` reads:
    - a child block by its drawn name;
    - a drawn unit designator (`U3B`);
    - a pin by any `/`-separated part of its name (`U4.RXD0`);
    - a sheet by its ID.

    Messages name ports `port:NAME`, parts by designator and nets by name. `refs` keep keys.
  - **One answer shape** (F15). `place` answers `description` as `describe` does (`blocks: [..]` of one), its `scores` that description's, with or without `--dry-run`.
  - **A dry run renders** (F16). `place --dry-run --render FILE [--format png|svg] [--scale S] [--fit]` draws the proposed layout, the bytes after the answer. `layout --relayout --dry-run` doesn't render yet. The round's wrapper refuses `--render` in describe-only sessions.
  - **Boxes and pins** (F17). `describe` gives each part's `box_mm` and its connected pins' `at_mm`, `side` and name, and ports' names.
  - **Sheets** (F18). `sheet rename S NAME` renames a sheet (by ID or name), and a layout drops a sheet nothing stands on. The plan's "`sheet` moves only what it names" needed no engine change: the round's case was `sheet X s1` making a new sheet called `s1`, which reading a sheet by its ID ends. Sheet overflow (`sheet_full`) is 1.D's placement work.
  - **Quoted refusals** (F12). A batch's per-instruction refusal gives the instruction's `text` beside its index.
  - **The score** (F19). Each sheet gives `penalty`, its findings' points before the clamp. Two new rules:
    - `sch_part_flipped` (3 a part): a two-pin part with its ground end up or supply end down; its message says `orient X 180`;
    - `sch_wire_wraps` (3 a wire): a run going round two opposite sides of the part it ends on.
  - **Findings an agent can act on** (F20). `sch_out_of_line` counts a part and its idiom satellite as in line with each other: a pull resistor with a pin end on the line out of its pin, or a bypass capacitor wired to its pin. `sch_idiom_missed` judges a jumper joined to a pull idiom against the idiom's resistor.

  F3 to F5 and F21 (pin-level `align` and a nudge, "in parallel" for a stage's feedback, verbs that move the least and keep a part's sheet, placement across clusters) are 1.D's (work item 4530 for the last).

## Agent round 2 and the verdict (decided in ryueda phase 1)

The design is document 236 in the Coxswain planning project `ryucad-ryukei`; this is its phase 8, plan 1.D. The report is document 343, the gallery `cox visual` 01M6G26710J01WRVTEHGJ4CRGM.

- **Placement across clusters** (work item 4530).
  - **Guests beside their hosts.** After flow from nothing, a loose cluster stands beside its host (`engine::guest`, `beside_host`): a cluster of parts of at most 8 pins, no connector, no part an `edge` or `sheet` instruction holds, none powered by a supply, and no block symbol. Its host is the part it shares most signal nets with, ties going to a connector, then the least key. A block symbol is a guest only of a part with more pins.
  - **Local wiring.** A labelled net's pins within `LOCAL_REACH` (16 steps; the plan said 12, which left the corpus's floating parts above the bar) are wired pin to pin before labels, and only on a layout from nothing. Labels go to parts with more pins first. A pin wired locally before keeps its wire, rather than its net's old labels.
  - **Flags beside their pins.** A port's flag whose net has one pin (`place::sole_pin`) joins that pin's cluster six steps out. An in-flag beside a pin pointing right keeps its edge; an out-flag on a left pin is mirrored.
  - **New parts.** A new part is inserted beside its host.
  - **Result.** Laid out from nothing, the corpus floats 16 parts, down from 35, against a bar of 20.
- **The verbs.**
  - **Moving the least.** `beside`, `near`, `align` and `shift` move their parts as soft parts: kept where they were, then moved by `relate` along their line (`spot_along`). They never change a part's sheet: `align` across sheets doesn't hold, and its `why` says so. A move that drops a sheet's score by more than 10 points is noted (`move_costly`).
  - **Pins and shifts.** `align` takes pins (`align J1.3 U2.SCL row`, `instr::Lined`), which makes the layout file format 2. `shift X up|down|left|right N` (1 to 40 steps) is a move only: as a lasting instruction it is `invalid_param`, and one breaking a hard rule is `layout_rule`.
  - **Re-forming a stage.** A lasting `idiom X opamp_stage|buck` re-forms the stage, its nets asked to be wired. `sch_topology`'s message ends with the instruction that draws it so (`topology::Judged::fix`).
- **Looking.** `layout --dry-run --render FILE [--format] [--scale] [--fit]` draws a relayout before it is written. `lint --explain CODE` gives a rule's catalogue entry (see the Lint paragraph above). Findings carry `fixes`, and `describe` and `check` write them as text. `lint configure --dry-run` answers each sheet's score before and after a change of preferences, and the findings that come and go, writing nothing.
- **References measured.** `scripts/schematic-refs/measure.py` counts a KiCad sheet's wires, crossings (no junction there), junctions, labels and power symbols by direction. `tests/schematic_corpus/manifest.txt` records each reference's `crossings` (breakout 3, Mitayi-Pico-D1 1, buck 0, front end 5, ESP32-PoE 33), which `schematic_refs.rs` reads.

  - at most 20 floating parts;
  - crossings at most 1.5 times its reference's (at least 1);
  - each block's score at or above its threshold.

  From nothing it draws crossings of 2 (breakout), 2 (RP2040), 0 (buck), 4 (front end) and 5 (Ethernet). Exceptions:
  - the Ethernet PHY's `eth` sheet scores 0 and is excepted by name, naming issue #429 (satellites of a dense IC);
  - the buck reached 0 crossings once hanging satellites stand in stairs (`idiom::hanging_stairs`, the lowest pin's nearest) and its boot capacitor joined the buck idiom.

  `the_corpus_from_nothing_findings_carry_fixes` holds the fixes to working.

It uses seven criteria, three fresh judges a pair and seed 236. `cargo run -p ryueda --example svg-png` draws the references' SVGs as PNGs.

## Regions and paper fit (decided in ryueda phase 2)

The design is document 348 in the Coxswain planning project `ryucad-ryukei`; this is its plan 2.A (phases 1 and 2).

- **Regions.** A region is a titled rectangle on a sheet holding one function's parts (`layout::Region`: `sheet`, `at` its origin, `frame` relative to it, `title`, `named`, `parts`). `region::propose` proposes them in design 348's order: named regions (`region` instructions), each recognised topology (a buck, an op-amp stage: `<value> converter`, `<value> stage`), each active part of more than 8 pins (`region::DENSE`) with the idioms it anchors and the guests whose host it is (`<refdes> <value>`), each connector with its idioms and guests, then each connected group of what is left over signal nets, titled by its busiest signal net (the whole block's pins on it, ties by name), else `Misc` (question 213). A part an `edge` instruction holds is grouped with nothing. A component's `function` (its parameter, else its first layer's instances, its block, the project: `Part::function`) titles the region it leads; the agent's title always wins. Block ports are in no region (question 212); a port an idiom's cluster holds beside the pin it meets moves with the region. Every idiom's parts follow their anchor. IDs are `r1`, `r2`, … in proposal order, one past the largest over a previous layout.
- **Frames.** Worked out after drawing from what a region holds (`region::frames`): its parts' extents, their text and the labels on their pins, grown by `region::FRAME` (2 steps), the title band (`region::TITLE`, 3 steps) on top. Where two frames would still overlap (a value grown longer, a part an instruction moved, labels drawn), the later unnamed region joins the earlier and the frames are worked out again, so frames never overlap after drawing; named regions are never joined away.
- **Two-level packing.** From nothing (`engine::pack_regions`), each region's clusters are flowed onto a sheet of their own and drawn to their hosts into one framed cluster (`Cluster::frame`: its room holds a label on every pin whose net leaves it, its margin and title band); a region past one sheet splits into `<title> (2)`. The region clusters and the ports are then flowed onto the block's sheets, so signals between regions order their columns and regions joined only by rails go in the top band. A part a `beside` or `near` instruction moves joins the region of the part it stands by.
- **Layout format 3.** A layout with regions, a sheet's own paper or a region or paper instruction is written at format 3 (`Layout::format`), each region's parts placed relative to its origin (`Layout::relative`; `read_layout` gives sheet coordinates through `Layout::absolute`), so a region's move is one key in the file, the diff and the merge. Formats 1 and 2 read as layouts with no regions.
- **Instructions.** `region TITLE X...` (a named region, lasting; a part in two is `instruction_conflict`), `region none X...` (out of named regions), `region rename REGION TITLE` (vocabulary only: a lasting `region` over the region's parts now, replacing one naming only them), `paper SHEET SIZE [landscape|portrait]` (pins the sheet's paper; a size the series lacks is `layout_rule`), and regions as subjects: `region:<id>` or a region's title wherever a part goes; `sheet` and `edge` act on its parts, `beside`, `near` and `align` move it whole, its origin with it. A region ID the layout no longer has is the note `region_unresolved`.
- **Incremental regions.** Over a previous layout regions are kept with the parts kept; named regions hold their parts; a new part joins its host's region (or a named one it is listed in) in the free space beside the host within the frame grown by `region::WIDEN` (4 steps), else the nearest free spot (the region grows there; a departure from the plan, so nothing kept moves where there is room), the grown frame clear of every other region; else the region moves whole with it; else its sheet grows one paper size (`sheet_resized`, unless pinned or at the largest) and it tries again; else the region and it go to a new sheet (`sheet_full`, with the region and the fix `sheet region:<id> <sheet>`). A part placed by itself gets a region of its own.
- **Hard rules.** `region_overlap` (frames on a sheet apart) and `region_holds` (each frame holding its parts, their text and labels; a part in one region at most).
- **Drawn.** A region is a dashed frame (2 mm on, 1 mm off, `paint::FRAME`, the symbols' colour at 45% over the paper) with its title in a tab filled with the paper (`paint::Item::Frame`), under everything; SVG and the PDF draw it alike.
- **The merge.** `merge::merge` compares each side in the file's form, regions as keys, so a region moved on one side and a part edited inside it on the other merge cleanly; both moving one region is a conflict over its frame.
- **The paper series.** The manifest's `schematic.sheet` gains `fit` (true) and `sizes` (`a4`, `a3`), written only when they differ; `Sheet::series` is the sizes up to `size`, smallest first, `size` last, none with fit off. ryueda passes it as `Block::papers`; each sheet's area is its own paper's (`Block::area_of`), a sheet at the project's paper writing no size. `project edit --fit --sizes`.

## Dense ICs and the agent's asks (decided in ryueda phase 2)

The design is document 348 in the Coxswain planning project `ryucad-ryukei`; this is its plan 2.B (phase 3).

- **Banks** (`idiom::banks`, `place_bank`; #429). The pull-ups and pull-downs on one sideways side of a part of more than `region::DENSE` (8) pins form a bank when two rows or more of that side hold a pull resistor (a pin's capacitors alone, a regulator's VDDCR pair, keep phase 1's places; a pull with a jumper too). Each row's first member (resistors first, then by key) stands across the page on its pin's row, its signal end towards the part at one column past what the side's rows put out (their net labels, the part's room, other members beside the rows) and two steps; each rail's far ends stand in one column, so the rail comb draws a bar and a port a run. The rail nearer the part is the one whose bar the other rail's rows cross least (its port standing in a far row's way counts two), a rail whose rows hang second members always far, ties to ground. A row's second member hangs two steps off its wire, between the columns on a far row (where no near row's wire runs).
- **Two rule departures** (agreed by the coxswain). `spacing`: two parts of two pins lying across the page on different rows may stand closer than a step, their extents still apart (a bank's rows are two steps apart; a 40 mil resistor across leaves 20 mil). `overlap`: a wire of a net label's own net may run along the label's line (a net label is a name on its wire); its text stays off limits to every wire. `rules::tests` hold both cases each way.
- **Rows that carry a name.** A bank row whose net reaches a port or a pin beyond the row is drawn as a wire from the pin to its members with a net label on it at the pin (`engine::BankRow`); the port's flag stands with the block's ports, flow no longer lining it up with the row (`Hints::apart`). Only a row whose first member stands on it is drawn so; a member kept elsewhere is drawn as any part.
- **Text on one line.** A bank row's first member writes its designator and value on one line (`text::row_line`, `row_points`) on the grid line under its row, else on the row's own, past its rail end; the far column reserves that width.
- **Arrays and networks.** An array's two-pin units (`RN`, `RM`, `RA` as well as `R`) are resistors, as the lint reads them. A one-symbol network (four pins or more in level pairs, no idiom's part) whose signal pins each meet one sideways side of one part joins that part's cluster beside the side, its signal pins facing it, past what stands beside the rows (`idiom::place_networks`).
- **Pulls serve the dense part.** A pull on a net several active parts share serves the one of more than 8 pins (the PHY's line terminations serve U4, not the ESD array); crystals and dividers keep phase 1's first by key.
- **Decoupling past a bank.** A decoupling row's reach counts a bank's members on its side whatever their height.
- **The lint along a row.** A pull wired to the pin it serves, on its row or hanging two steps off it, is the pin's however far out (`sch_idiom_missed`'s `what` and `evidence` say so).
- **`text X... refdes|value|both left|right|above|below`** (`Instruction::Text`, `TextField`, format 3): the field (or both as one block) at the first free place wholly on that side of the body (`text::candidates_on`), the rest where phase 1 puts it; two asks giving one field different sides conflict. Kept text is kept field by field, at each field's own point.
- **`near X Y... P`** with two parts or more and a pin of a part of three pins or more: one network (`instr::Resolved::networks`, `idiom::Asks`), walked from the pin through two-pin parts: parts to a rail stand off their node, parts to a signal go across the page, all in the pin's part's cluster, so it moves whole. Parts the walk doesn't reach, parts of more than two pins, and parts a `region` instruction holds apart from the pin's part are left where they are, noted `network_unresolved` (a departure from the plan, which moved them near the pin alone: phase 1's `near` to a pin breaks hard rules on seeded blocks, to be fixed apart). A network holds where each part is within the idiom reach of the pin's part or of another part of it.
- **`near port:NAME P`**: the flag joins the pin's part's cluster six steps out on the pin's row, mirrored where it would read backwards, whatever else the net reaches; a banked row wins, noted `port_row_banked`.
- **Turned stages.** An amplifier oriented 0 or 180 degrees keeps its `opamp_stage`: the feedback above it turned towards the inverting pin's side, the input element on that side (the topology judge reads that side). At 90 or 270 the stage is dropped, noted `orient_drops_stage`.
- **`--sheet`** with `--render` on `place` and `layout` dry runs draws one sheet (by ID or name); an unknown one is `not_found`.
- **Release restores** (`Layout::before`, format 3; `Block::restore`). For each lasting instruction a batch adds, the places of the parts it moved; the engine carries them while the instruction lasts, merges keep them with their instruction. Releasing it puts each part back where its extent is still clear (a bank's spacing for parts across the page), in its host's region.
- **Fixes tried first** (`lint::try_fix`, `schem::checked_findings`, `FIX_CHECKS` = 24 a block, the findings with most points first, in parallel). A fix is offered only if the engine takes it as lasting instructions, every hard rule holds, the layout changes and the finding is gone; a finding past the cap says `fixes_checked: false`. From nothing every fix the corpus offers removes its finding.
- **Holds say why** (`Outcome::blocked`). A relative instruction's part the engine couldn't put where asked records what stood there (designators, a wire or label) or that the sheet had no free place; the listing's `why` adds it, and an unchanged move's note gives `details.blocked`.
