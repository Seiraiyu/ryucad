## The Python client (decided in ryucad phase 32)

The design is document 697 in the Coxswain planning project `ryucad-ryukei` (#841); plan 32.A built the package, plan 32.B published it.

- **What.** `python/`: the distribution `ryucad` on PyPI, imported as `import ryucad`, one pure-Python wheel (`py3-none-any`, hatchling at build time), standard library only, Python 3.10 and newer, Apache-2.0 with `LICENSE` and `NOTICE` in the wheel. It is a thin client over `ryucad session --stdio` (`ryucad-scripting.md`): methods, params and answers are `proto`'s, and the package adds the process, the framing, typed errors and the three requests a script lives on (`batch`, `part.ensure`, `undo`). No per-method wrappers, asyncio, programmatic cancel or timeouts.
- **Finding ryucad.** `connect(exe=...)` (a path, or a command line as a list), else `RYUCAD_EXE`, else `ryucad` on `PATH`, else the installers' `bin` (`RYUCAD_HOME`'s, else `~/.ryucad`'s); none is `NotInstalled` with the install commands. It never bundles or downloads a binary: two ryucads of different builds on one machine would replace each other's daemon on every connection. `connect` runs `ryucad version` once: protocol below 3 is `Incompatible`; a binary older than the package (both `X.Y.Z`, pre-releases dropped, `0.0.0` ignored) is a `warnings.warn`.
- **The session.** `connect(folder, as_, no_daemon, exe, env, on_progress)` starts `ryucad [-C] [--as] [--no-daemon] session --stdio`, stdin and stdout piped, stderr inherited; `env` is the child's whole environment. `call` writes compact JSON lines (`ensure_ascii=False`) and reads UTF-8 bytes to `\n`, then exactly `binary.length` bytes into `Answer.data`. Relative paths mean `connect`'s folder (`-C`'s rule since 31.A). `progress` lines go to `on_progress` (an exception it raises is held until the answer is read); notifications, after the script's own `subscribe`, collect in `cad.notifications`. A lock makes one request at a time. On `KeyboardInterrupt` while waiting, the client reads on until the `cancelled` answer or the child's exit, then re-raises. The child exiting or a broken pipe is `SessionClosed`, for that call and every later one; a refusal at the start (null id) is raised as its own class by the first call.
- **Errors.** `RyucadError` carries `code` (a `Code`, or the plain string for a code the package doesn't know), `message`, `details`, `pointer`, `path`, `op`, `method`. One subclass per exit class (`FixableError` 1, `UsageError` 2, `ProjectError` 3, `ExternalError` 4) and named ones for the codes scripts branch on (`Conflict`, `NotFound`, `RebuildFailed`, `HasDependents`, `AssemblyOverconstrained`; `Cancelled`, `DaemonError`), added only when a script needs one. Client-side: `NotInstalled`, `Incompatible`, `SessionClosed`, `ProtocolError`.
- **Codes held in step.** `ryu_doc::error::Code::ALL` is a plain list, checked against the enum by a test that reads `error.rs` (a `macro_rules!` around the enum would hide it from rustdoc and go-to-definition). `crates/ryucad/tests/python.rs` renders `python/src/ryucad/_codes.py` (`Code`, a `str` `Enum`, and `EXIT`) from `Code::ALL`, serde's names and `exit_code`, and fails when the committed file differs; `UPDATE_PYTHON=1 cargo test -p ryucad --test python` rewrites it.
- **Tests.** `unittest` only. Unit tests against `python/tests/fake_session.py` (no ryucad); integration tests (`test_session.py`) skipped unless `RYUCAD_EXE` is set, each in a new temporary project outside every Git repository with private runtime, config and cache folders, through the daemon and in process. `tests/python.rs` runs them all against the binary the workspace built (Linux x64's PR partitions; full.yml on every platform with `RYUCAD_REQUIRE_PYTHON=1`, so a missing `python3` fails). ci.yml's `python` job (3.10 and the newest stable, pinned by number): unit tests, `scripts/python-dist.sh`, `twine check --strict`, `ruff check` (rules `E F W B UP I`) and `mypy --strict`, with ruff and mypy pinned so a tool's release can't fail a pull request.
- **Version.** From ryucad's tag, never a file: `python/pyproject.toml` holds `0.0.0`. `scripts/stamp-version.sh` stamps it only when given the `v` tag form (`vX.Y.Z` → `X.Y.Z`, `vX.Y.Z-pre.N` → `X.Y.ZrcN`, `vX.Y.Z-dev` → `X.Y.Z.dev0`; any other suffix refused before anything is written). Every workflow's build jobs and full.yml pass the bare version, and ryueda's and ryudfm's tags, so they leave it alone; release.yml's `python` job passes `v<version>`. `ryucad.__version__` reads `importlib.metadata` (`0.0.0` from a checkout). Tested in `crates/ryueda/tests/release.rs`.
- **Building.** `scripts/python-dist.sh` copies the root `LICENSE` and `NOTICE` into `python/` (hatchling can't name files above it; `python/.gitignore` keeps the copies out), builds the wheel and sdist into `python/dist` and checks the wheel carries both licences. `PYTHON` names the interpreter.
- **Publishing (32.B).** release.yml, on ryucad's tags only: `python` (beside `build`, dry runs too: stamp, build, `twine check`, unit tests against the installed wheel with `python/src` removed, the `python-dist` artifact); `testpypi` (after `publish` and `python`; environment `testpypi`); `python-verify` (after `testpypi` and `installers`; Linux on 3.10, macOS and Windows on the newest: ryucad from the release's installer, the package from TestPyPI with `--no-deps`, retried two minutes, `python/src` removed, the integration tests against the binary `ryucad.find()` locates); `pypi` (after `python-verify`; environment `pypi`). Both uploads use `pypa/gh-action-pypi-publish@release/v1` by trusted publishing (`id-token: write` on those two jobs only; no token or secret anywhere; PEP 740 attestations kept) with `skip-existing: true`, so re-running failed jobs finishes a release. `publish` never waits on the Python jobs. Pre-releases publish `rcN` to both indexes. `crates/ryueda/tests/release.rs` pins each job's shape, that only those two jobs mint OIDC tokens, that no release workflow reads a secret, and that ryueda's and ryudfm's never publish the package.
- **The owner's one step.** A pending trusted publisher for project `ryucad` on pypi.org and on test.pypi.org (owner `Seiraiyu`, repository `ryucad`, workflow `release.yml`, environment `pypi` and `testpypi` respectively), registered once; the first upload turns each into the project's publisher. Until it is registered a tag's `testpypi` job fails and a re-run finishes it. Raised by the coxswain as an owner task, never a plan step.
- **Not here.** The corpus scripts stay CLI-only (they test the CLI). No MCP server (CLAUDE.md's open decision), no ryueda or ryudfm client (no `session --stdio` there yet), no conda-forge or Homebrew.
