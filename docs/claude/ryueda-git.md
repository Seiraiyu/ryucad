## Revisions, attributes, textconv and doctor (decided in ryueda phase 4)

The design is document 518 in the Coxswain planning project `ryucad-ryukei`; this is its phase 2, plan 4.A.

- **Revisions.** `netlist`, `erc`, `check`, `describe`, `render`, `output`, `block.show`, `component.show`, `net.show`, `symbol.show`, `libcomp.show` and `lib check` take `rev` (CLI `--rev`), `working` (the files on disk) by default. `ryueda::git::revision` reads the project from Git's objects (`ryu-git`, `Layout for Eda`: the root files, `designs/`, `rails/`, `classes/`, `blocks/`, `library/`) and each alias's library project from the same commit, its path resolved inside the repository (`library_missing` naming the revision when it leads out, isn't there, isn't a library project; `library_nested`), and loads it with `Project::load_from`. The session keeps `REVISIONS` (4) by the project's tree and its aliases', most recently used first. Answers carry `commit` (a raw answer's text gains it as its first member; an error at a revision carries it in its details). `not_a_git_repo` outside a repository, `rev_not_found` for a revision it lacks.
- **Attributes and install.** `init` writes `.gitattributes` (`ryueda::drivers::LINES`: the manifest, `erc.json`, `lint.json`, `parts.json`, `style.json`, `designs/*.json`, `rails/*.json`, `classes/*.json`, `blocks/**/*.json`, `library/**/*.json` get `merge=ryueda diff=ryueda text eol=lf`; `library/models/** binary`; `.gitattributes text eol=lf`), and inside a repository runs `git install` (its answer's `git`). `ryueda git install [--global]` writes `diff.ryueda.textconv`, and in the clone `merge.renames=false`. The merge driver's entry and ryueda's line in the shared hook come in plan 4.C; until then Git merges the files as text (a `merge=` attribute naming a driver Git's config lacks). The installers run the global form when Git is there.
- **Textconv.** `ryueda git textconv <file>`: `<kind> format <n>`, then one sorted line per value. Components by field and pin (`of = self/r_0402`, `pin 1 = net <id>`, `pin 2 = rail <id>`), blocks' ports and buses one line each, layouts in ryusch's key space (`placed/R5 = sheet s1 at 50.8 mm, 25.4 mm, 90 deg`, `labels/<net>|<part>/<pin> = …`, `routes/<net>|<sheet> = …`, `instruction i3 = …`), symbols per pin and graphic, footprints per pad, graphic and keepout, styles per palette entry, numbered rule (`rule 001`) and override; the rest flattened by key. Other objects are named by ID. Anything that isn't JSON comes back as it is.
- **Doctor.** `doctor` (`ryueda doctor [--repair ID…]`; `doctor.repair`, one logged, undoable change): `gitattributes_missing` (repair: the lines added, the rest kept), `git_drivers_missing` (repair `git_install`, Git's config: not logged), `unmerged_path` (an error), `non_canonical` (repair: written canonically), `unknown_file` (the loader's warning, now that code) and `model_orphaned` (repair: removed). Repair IDs are `<code>:<action>:<file>@<hash of the files>`; a stale one is `repair_conflict`. `check` reports doctor's issues under `doctor` (all but `unknown_file`, already among its faults); `check --rev` has none. Doctor needs a project that opens: a manifest that doesn't read fails it as every request.
- **Testing.** Unit tests (`git`, `session`, `drivers`, `textconv`, `doctor`), `tests/git.rs` (reads at a revision both ways, `init` in a repository, `git install`, `git diff` through textconv, doctor's repairs undone through the daemon, `check`'s doctor), the installers' tests.

## Diff and compare (decided in ryueda phase 4)

The design is document 518 in the Coxswain planning project `ryucad-ryukei`; these are its phases 3 and 4, plan 4.B.

- **Diff.** `diff` (`ryueda diff [--from REV] [--to REV] [--design D] [--block B] [--netlist] [--layout] [--library] [--all]`; `HEAD` and `working` by default) compares two revisions' files as JSON, as written (`ryueda::diff`, ryucad's rule), names resolved through each side's loaded project: the root files and `designs/`, `rails/`, `classes/` by pointer; per block its `block.json`, `ports` and `buses` by member, components, nets and instances by object with a pin's or port's change as `pin 3: SDA → SCL` (listed when its node differs by ID, so a renamed net reads as its `name` changed), each entry with its `file` and reference path (`schem::ref_path`: `<block>/<layout key>`, a unit's `:<n>` dropped, a label `<block>/label:<net>@<component>/<pin>`); the layout's counts, or with `--layout` each key (`ryusch::diff::layouts`, `ryusch::merge`'s key space; a place alone changed on its sheet is `moved`) and the instructions added and dropped as an agent writes them; the library's counts, or with `--library` each object by member (`lib/<alias>/<kind>/<id>`) and models by BLAKE3. `--netlist` flattens each design on both sides: occurrences `added`, `removed` and `changed` (`refdes`, `value`, `footprint`), nets by their highest node (`renamed`, `added`, `removed`, pins `joined` and `left`), and ERC findings `appeared` and `gone`. A file that doesn't parse is `invalid`, naming the side.
- **Check.** `check --against REV` adds `diff --netlist` from that revision to the working files (`against`, in the report or in `check_failed`'s `details.report`); with `--rev` it is `invalid_param`. A file holding a conflict record (a top-level `conflicts` object) fails to load as `merge_conflict` (`doc::CONFLICTS`) and doctor lists it; Git's unmerged paths are doctor's `unmerged_path`; either fails `check`.
- **Compare.** `ryusch::paint::Painted::owners` gives each item its layout key (design 519's table: a part's, a net's for its wires and junctions, `bus:`, `region:`, `note:`, `label:<net>@<part>/<pin>`; `None` for a layer's bounds), read by no SVG or PDF. `ryueda::compare::marks` marks a block's sheets against a revision: owners whose object's file is new or differs, or whose layout keys were added or changed, `Added` or `Changed`; a place alone `Moved`; what only the revision has (and a changed wire's old runs) ghosted. `ryusch::paint::compare` paints them: ghosts first, dashed and unfilled in `diff_removed`, then the working items, marked ones in `diff_added` or `diff_changed`, a moved part's dashed leader, and the strip (`Against <rev>: N added, N changed, N moved, N removed`) under the sheet. `render --compare REV` (SVG, PNG) draws that with each owner's items in `<g data-ref="<reference path>">` (only there: every other SVG keeps its bytes); `--rev` with it is `invalid_param`. `output --compare REV` pages only the changed sheets, without cross-references or block links, and answers `unchanged: true` with no file when none changed. The roles `diff_added`, `diff_changed`, `diff_removed` (`#1a7f37`/`#3fb950`, `#9a6700`/`#d29922`, `#cf222e`/`#f85149`) are palette names like any other: they cascade, lock and lint (`sch_contrast`'s paper list).
- **The participant's compare.** `compare.set` (`ryueda compare REV`, `--off`) sets `participant`'s, else the one human's, else the caller's (`live::compare_target`), the revision as given in `ryueda::view::View`, which `participant.changed` carries; the revision must name a commit holding the project, `working` is `invalid_param`. `compare.get` (`ryueda compare`) gives the same participant's (so an agent with no human attached reads back its own) and the commit it names now. Stage 3 adds its sheet and camera to the same view.
- **Testing.** Unit tests (`diff`, `schem::ref_path`, `ryusch::diff`, `paint`'s owners and compare, `svg`'s `data-ref`), `tests/git.rs` (diff both ways, `check --against`, an unfinished merge, `render --compare`, `output --compare`, `compare` through the daemon), `tests/cli.rs` (the diff roles linted, parity), and `tests/golden/ryueda.txt`'s `diff.breakout*` and `schematic.breakout.compare.*` (the breakout edited: a value, a part added and one deleted, a net renamed, a part moved). No existing golden moved.

## The merge driver (decided in ryueda phase 4)

The design is document 518 in the Coxswain planning project `ryucad-ryukei`; these are its phases 5 and 6, plan 4.C.

- **Driver.** `ryueda git merge-driver %O %A %B %P` (`merge.ryueda.driver`, written by `git install` locally and with `--global`; CLI only, prints nothing) merges by value through `ryueda::merge::bytes`: UTF-8 JSON with a `kind` and a `format` no newer than this build reads, no conflict record. Anything else merges as lines (`ryu_git::value::text`), exit 1. A kind changed on a side, or a file added on both sides differently (`id_collision`), is one value. The result is canonical, at the lowest format that holds it (`conn::format_of`, a symbol's `class`, a library component's `category`/`alternates`, the manifest's `properties`/`schematic`; the greater side's otherwise).
- **Rules** (`ryueda::merge`, over `ryu_git::value`'s walk). One value each: a component's `of`, `footprint` and each `pins/<n>`; a net's `pair`; an instance's `ports/<p>` and `refdes`; `erc.json`'s `waivers/<id>`; `style.json`'s `palette/<name>`; a symbol's `pins/<n>` and `graphics/<id>`; a footprint's `pads/<id>`, `graphics/<id>`, `keepouts/<id>`; a library component's `symbol`, `category` and each footprint's `footprint`. Sets (added by either, removed by either, written sorted): components', nets' and rails' `tags`, `style.json`'s `locks`. A library component's `footprints` merge by footprint (`<library>/<id>`) in order (`ryu_git::value::order` at `/footprints`), each one's pin map by pin. Every other key per key, an array one value (a bus's `nets`, `rules`, `offers`, `alternates`, `models`). `ryueda::merge::settle` puts a chosen value back the same way.
- **Layouts in the driver.** A `ryueda.layout` one side changed (or both alike) is that side's; changed differently, it is ours' with a whole-file `layout_pending` entry holding all three. The driver never reads other files or lays out.
- **Status.** `merge.status` (`ryueda merge status`; `ryueda::validate`) lists, each with `id`, `kind`, `files`, `concerns` (`block`, `refs` as stage 3's reference paths), `cause`, `message`, `choices`, `repairs`: record entries (`<path>#<pointer>`: `value`, `delete_edit`, `order`, `id_collision`, choices `ours`/`theirs`/`value`), unmerged paths (`<path>#`: `modify_delete`, `merge_unparsed`; model files by BLAKE3), and layouts. Settled files waiting for `git add` are `unstaged`. The answer is kept by the merge, the index's stamp and the working files' digest (`Session::merge_status`, `Session::digest`).
- **Layouts at status time** (phase 6). A pending block, once nothing else is listed: `ryusch::merge::merge` over the session's merged connectivity (`validate::block_merge`: `schem::build`, the merged instructions' notes) with each side's layout from the merge's commits. Each area both sides changed is `layout_conflict` (`<block>#area:<n>` from 1; `areas` by sheet, `keys` per side, `with` every area ID of the block; choices `ours`/`theirs`, repair `relayout` first). A clean three-way merge is `layout_stale` (`<block>#layout`; repair `merge`). While other items are listed, or the project doesn't load, a pending block is `layout_pending` (choices `ours`/`theirs`). A block no record names whose files (its folder, every `block.json`, everything outside `blocks/` but `erc.json`, `lint.json`, `parts.json`, `.gitattributes`) differ from both sides' and that `schem::lay` finds stale or invalid is `layout_stale` with repair `relayout`. All block the commit.
- **Resolve.** `merge.resolve` (`ryueda merge resolve <id>… --ours|--theirs|--value JSON|--repair ID [--expect REV]`; every ID takes the choice given) settles a batch in order in memory and writes all or nothing, atomically, as one logged, undoable change; it never touches the index. A block's areas are settled in one batch (`invalid_param` names the rest); `ryusch::merge::resolve` lays the block out once, refused as the engine refuses (`layout_rule`, `instruction_conflict`); every layout written is laid out once more over the batch's files (`validate::current`), so it reads current. `--expect` guards the first conflict's block revision, else the project's (`validate::scope`). Errors: `not_merging`, `conflict_not_found`, `repair_conflict`, `conflict`.
- **A manifest's record.** No session opens over it, so `handle_job` answers `merge.status` and `merge.resolve` from the files alone (`validate::unloaded`: records and unmerged paths, pending layouts as `layout_pending`), the resolution written but not logged (`unloaded: true`).
- **Hook.** `DRIVERS.hook` is on: ryueda's line in the clone's shared `pre-merge-commit` and `pre-commit` runs `ryueda merge status --hook`, which checks every ryueda project the merge concerns in process, then that no project file differs from the index, and exits 1 saying what to settle; outside a merge it exits 0 at once.
- **Notification.** `merge.changed` (topic `merge`): `{merging: false}`, `{merging: true, status}`, or `{merging: true, error}` (said again once Git's waiting files move); read only while someone watches.
- **Doctor.** `git_hook_missing` (repair `git_install`, one per hook; or `core.hooksPath`'s hook, with the line to add) and `git_hook_foreign` (left alone, with the line to add).
- **Testing.** Unit tests (`ryu_git::value`, `ryueda::merge` per rule, `validate`), `tests/merge_props.rs` (proptest: one side's change, both alike, either way round, canonical, records refused), `tests/merge.rs` through Git (a value conflict refused by the hook and settled both ways, layouts by area with `relayout` and undo through the daemon, rebase, cherry-pick, `core.autocrlf=true`, ryucad's hook line beside ryueda's, `merge.changed`), and `tests/golden/ryueda.txt`'s `merge.breakout.status` and `merge.breakout.layout`. Semantic clashes (`refdes_clash`, `name_clash`, `delete_edit` with `follow`, library renumbering, `merge_faults`), the `eda_merge` fuzz target, the corpus branches, the bars and the agent round are plan 4.D's.
