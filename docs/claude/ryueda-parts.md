## Part data and library search (decided in ryueda phase 6)

The design is document 347 in the Coxswain planning project `ryucad-ryukei`; this is its plan 6.A (phases 1 and 2).

- **Crate.** `ryueda-parts` is part data alone: it depends on `ryu-doc`, `blake3`, `rayon`, `serde` and `serde_json` (`tests/deps.rs`), and knows no project or session. `dec` (exact decimals, 27 digits), `param` (the vocabulary), `category`, `record` (`Record`, `Offer`, `Terms`), `query` (conditions, ranking), `source` (the `Source` trait, `Call`, `Key`), `library` (the `library` source) and `cache`.
- **The vocabulary.** Thirteen names with a kind (`param::VOCABULARY`): `resistance`, `capacitance`, `inductance`, `voltage_rating`, `current_rating`, `power_rating`, `frequency` (electrical quantities, exact SI values through `ryu-doc`), `tolerance` (a ratio, or a quantity such as `±0.25 pF`), `temperature_coefficient`, `dielectric` (`NP0` is `C0G`), `package` (any case), `operating_temperature` (a range in °C, or one temperature), `mounting`. Values match by value: `100nF`, `0.1 uF` and `100 nF` are equal. Names outside it stay text. One table maps sources' spellings onto it (`param::name_for`: `Voltage - Rated` is `voltage_rating`; bare `voltage`, `current` and `power` aren't mapped); KiCad import uses it, the first spelling a symbol gives winning. `conn::exact_value` (intent) reads through `param::quantity`.
- **Library components format 2.** `category` (one of 14, `Category::from_prefix` when left out; `libcomp show` gives `category` and `category_inferred`) and `alternates` (`[{manufacturer, mpn, offers}]`, after the first choice), written at format 2 only when a file has either (`libcomp::format_of`), so imports and every other file stay at 1. `LibComp::check_data`: a vocabulary parameter whose value doesn't read is `parameter_invalid` (a warning, with its pointer); an alternate without its maker or part number is `invalid_document`, a part number named twice `duplicate_id` (errors: writes adding one are refused). `libcomp create|edit` take `--category` (`""` back to inferred), `--alternate MAKER:MPN`, `--remove-alternate MPN` and `--alternate-offer MPN SUPPLIER=SKU` (protocol `category`, `alternates`, `add_alternates`, `remove_alternates`, `alternate_offers`); the design wrote `--alternate … --offer`, which would collide with the first choice's `--offer`.
- **Search.** `parts.search` (`ryueda parts search [CATEGORY] [CONDITION]… [--in library] [--stock N] [--basic] [--limit N] [--like REF] [--offline]`): conditions `name=value`, `>=`, `<=`, `~` (text contains), names in the vocabulary (`invalid_param` otherwise; a value that doesn't read is `invalid_quantity`; `>=`/`<=` only on ordered kinds). A part whose stated value fails is left out; one that doesn't state a parameter stays, its `unknown` naming it, and ranks after those meeting more (then by stock, then key). A range `>=` covers the asked one, `<=` lies within it; a temperature coefficient's bounds compare magnitudes; a ratio tolerance never compares with a quantity. Results are records (`{source, key, component, manufacturer, mpn, …, meets, unknown}`), a library's `component` and `key` `lib/<alias>/libcomp/<id>` (the design's `<alias>/<id>` is read by no command), with no supply fields. `--like` takes a library component or a placed `<block>/<component>` and searches with its category and readable vocabulary parameters. Only `library` is a source so far; other names are `invalid_param` until 6.B and 6.C.
- **Terms and the cache.** `Terms { store: cache | ttl(s) | never, write_parameters, attribution }`; `Terms::parameters_writable` is false for every source whatever an adapter says. `cache::Cache` lives in `parts` under ryueda's cache folder (`RYUEDA_CACHE_DIR`, else `%LOCALAPPDATA%\ryueda\cache`, `~/Library/Caches/ryueda`, `$XDG_CACHE_HOME/ryueda`), never in a project: `records/<2 hex>/<64 hex>.json` (BLAKE3 of source and key), kind `ryueda.part` format 1, written to a temporary file and renamed, a `never` source never written, a stale, unreadable or misnamed entry a miss that is removed, a newer ryueda's a miss left alone. Nothing in 6.A writes to it yet.
- **Identification in ERC.** `part_unidentified` (no `mpn`), `part_unsourced` (an `mpn`, first choice or alternate, with no offer; `details.mpns`) and `parameter_invalid` are warnings, once per placed library component, `refs` its reference then its occurrences, as `library_fault`. A component whose own or library parameters hold `dnp` (any value but `false`, `no`, `0`) isn't judged for the first two. `connector` and `other` parts are asked for a part number only when `erc.json` sets `part_unidentified`'s severity. The test fixtures (the breakout, the generated design, `Pair::with_resistor`) carry part numbers and offers, so their goldens didn't move.
- **Testing.** Unit tests per module of `ryueda-parts` (decimals at their edges, every kind's reading and refusal, spellings, categories, records and terms, conditions and ranking, the library source on one thread and eight, cache terms, corruption, newer entries and folders); ryueda's `libcomp`, `libcmd`, `erc`, `parts` and `kicad::import` tests; `tests/cli.rs`'s `footprints_and_library_components_from_the_cli` (warnings, categories, alternates) and `parts_from_the_cli`, both ways; the `parts.*` lines of `tests/golden/ryueda.txt` (`tests/support/parts.rs`'s seeded library); the `parts` fuzz target (`crates/ryueda-parts/tests/bytes.rs`'s checks); `tests/bar.rs`'s search over 10,000 library components (bar 50 ms, one thread): 9.9, 9.9 and 10.0 ms at worst of five, three runs on cox-worker-3 (Intel Core Ultra 5 250K Plus, 18 threads, shared, load average 2.1), release, `RYUEDA_BARS=1`.

## The JLC catalogue and supply findings (decided in ryueda phase 6)

The design is document 347 in the Coxswain planning project `ryucad-ryukei`; this is its plan 6.B (phases 3 and 4).

- **A connector, not a commitment** (the owner, on plan 387's question 248). The JLC/LCSC catalogue is reached only through `ryueda_parts::jlc`, listed once in `ryueda_parts::catalogue::CONNECTORS`; everything else sees a `Catalogue` (a `Source` with `fetched_at`, `created`, `parts` and `by_mpn`) and a `Connector` (`name`, the `suppliers` whose offer SKUs are its keys, `attribution`, `base`, `open`, `fetched_at`, `sync`). ryueda iterates `CONNECTORS` and asks a catalogue by name or by an offer's supplier. `tests/connectors.rs` holds that no code under `ryueda/src` or `ryueda-parts/src` names jlc or LCSC outside the connector's module and the table (tests and comments may; KiCad import's spellings of suppliers' columns are data, and allowed). Dropping the connector is deleting its module and its line. Nothing it downloads is ever committed: fixtures are written by us in its shape (`jlc::testing`).
- **jlcparts' files** (github.com/yaqwsx/jlcparts, published on GitHub Pages; `RYUEDA_JLC_URL` moves it). `manifest.json` (format 4 only: any other `version` is `parts_source_refused` naming it; file names with a path in them are refused), the gzipped attribute lookup table and every category's `shards` (gzipped JSON lines, a schema line first) are read; browse shards, search indexes, lookups and the SQLite cache are not. A file past 1 GiB unpacked, or that doesn't unpack, is refused; a row that doesn't read is left out and counted (`skipped_rows`).
- **The mapping.** Categories by words, the subcategory first (`jlc::category`: ferrite, LED, fuse, regulators, TVS, crystals), then the category, anything else `other`. Attributes by `param::name_for` and JLC's own names by category (a resistor's `Power` is its rating, a ceramic's temperature coefficient its dielectric), the primary entry's number in SI units written exactly by `param::si_text` (the float's shortest text, then the prefix that leaves 1 to 999: `100 nF`), tolerances (`percent`, a range about zero as its magnitude), ranges in °C, coefficients in ppm (`±100 ppm/K`), codes as text. Only what reads back as its kind is kept, and a record's `parameters` hold the vocabulary alone, so the index stays small. `Manufacturer` and `Basic/Extended` (`Preferred` is Basic) are fields; each record has one offer, `{supplier: "LCSC", sku: <C-number>}`, prices in USD as their text.
- **The index.** In the parts cache's `jlc/`: `current/meta.json` (kind `ryueda.catalogue`, format 1: source, `fetched_at`, the catalogue's `created`, parts, counts by category, attribution), a gzipped file of records per ryueda category (without the meta's source, time and attribution), and `keys.tsv.gz` (each key's category and squashed part number, so a lookup loads one category; an addition to the plan). A sync writes `next/` and swaps it in (`current` to `old`, `next` to `current`, `old` removed); a reader takes `current`, else the `old` a stopped swap left; a newer ryueda's index is no index. A key the catalogue gives twice is kept once.
- **The jlc source.** Terms `store: cache`, `write_parameters: false`, attribution "Data from jlcparts (yaqwsx/jlcparts), from JLCPCB's parts list". Keys `jlc:<C-number>` and `lcsc:<C-number>` (a connector by its name or a supplier it claims); `mpn:<part number>` asks every source. Each category is loaded once and kept, its records' vocabulary values read once (`query::Typed`, `Query::judge_typed`, which judges as `judge` does), searched in parallel and ranked as any source's.
- **Fetching.** `ryueda-parts` never opens a connection: an adapter asks a `fetch::Fetch` (tests a `fetch::Fake`). ryueda's `net::Https` is ureq 3 on rustls with ring (question 246: as ryucad and ryupdm build it; `ryueda`'s only C), 30 s to connect, 60 s quiet for an answer or a body, 512 MiB a file at most, the standard proxy variables. Every failure is `parts_source_unreachable` (exit 4) naming the URL, with `status` when it answered.
- **Long requests.** ryueda's first: `parts.sync` and `parts.refresh` (`Eda::LONG`) take `progress` and `token`, report phase `fetch` in `files` (a file a step), and stop at `request.cancel` (`ryueda cancel <token>`, answered by the daemon without its lock) before the next file; the download runs with the lock released (`Serve::prepare`, `Session::prepared`). The CLI gives every long request a token (`cli-<pid>-<nanos>`), `--token` names one, `--progress` prints `fetch: 3/1122 files (<file>)` lines on stderr. In process a sync reports its progress and can't be cancelled. A sync stopped or failed leaves the catalogue there was. The `progress` topic is ryueda's too.
- **Commands.** `parts sync <catalogue>`; `parts sources` (the library's components and faults, each catalogue `missing` or `synced` with `fetched_at`, `age_s`, `stale`, `parts`, `created`, attribution and the sync command, `max_age_s` and the cache folder); `parts show <source>:<key>` (`parts_not_found` naming what was searched; `--refresh` only says a catalogue refreshes by `parts sync`); `parts search --in jlc` (the library first whatever the order; the answer gains `sources` and `warnings`, which moved 6.A's three `parts.search` golden lines); `parts refresh [--force]` (question 247: syncs each catalogue the placed parts' offers draw on that is missing or past `parts.max_age`; 6.C adds per-part refreshes of live sources); `parts configure`. `libcomp create --from <key>` takes maker, part number, description, datasheet, category and the supplier offer, never parameters (they are listed under `from.parameters`, and a component written with none warns `parameter_missing_from`); fields given win; a symbol, first footprint and prefix left out are those the usable libraries' components of the record's category and package use most (ties: the least), reported in `chose`, a missing symbol `invalid_param` at `symbol`. `libcomp edit --from` takes each identifier the record holds that the fields don't give and the component's differs from, names them in `changed`, and writes nothing when nothing changes.
- **No catalogue, or an old one.** A search, show or check naming a catalogue this machine hasn't synced answers what the other sources give and warns `parts_cache_stale` with `reason: missing` and the command; past `parts.max_age` (a preference in seconds, an hour to a year, 7 days by default; `RYUEDA_PARTS_MAX_AGE` for tests; ryueda has no `config` command yet) with `reason: old` and its age. A session keeps the catalogues it opened and lets one go when its index's `fetched_at` moves, so a sync is seen at once.
- **`parts.json`.** Beside the manifest (kind `ryueda.parts`, format 1, written only when set, hashed into the project's revision only when present, tracked): `assembly` (`jlcpcb`), `build_quantity` (1 when left out), `sources` (which a search without `in` asks, in order), `severity` by supply code. Faults at their pointers (`/build_quantity`, `/severity/<code>`, `/sources/<i>`). `parts configure [--assembly jlcpcb|none] [--build-quantity N|default] [--source S]… [--no-sources] [--severity CODE=LEVEL|default]…` is one logged change guarded by the project's revision, the file deleted when it holds nothing.
- **Supply findings** (`supply.rs`), in `check` as `supply` (`source: supply`), from the catalogues this machine holds, never fetched (`check --offline` changes nothing yet): once per placed library component per design, `dnp` occurrences left out, `refs` the component and its occurrences, each with the record's `fetched_at`, `attribution`, `source` and `key`. `part_no_data` (it has offers and no source here holds a record of any), `part_out_of_stock` (every first-choice record stating a stock has fewer than placed × `build_quantity`; names the first alternate whose record clears it), `part_extended` (`assembly: jlcpcb` and every first-choice record that states it is Extended; names the first Basic alternate), `parts_mismatch` (a record's part number isn't its choice's, letters and digits without regard to case), and `parts_cache_stale` once per catalogue the placed parts draw on that is missing or old (with none synced, nothing else). Warnings unless `parts.json` sets a severity (`off` leaves it out); an error fails `check`. So a project whose parts carry LCSC offers now checks with one warning until the catalogue is synced. `part_lifecycle` is 6.C's.
- **Codes.** `parts_source_unreachable` (exit 4), `parts_source_refused`, `parts_not_found`, `parts_cache_stale`, `parts_mismatch`, `part_out_of_stock`, `part_extended`, `part_no_data`.
- **Testing.** Unit tests per module (quantities written as text, typed judging, the fake fetcher, the manifest and table, categories, attributes with the published table's shapes written by hand, shards, the index and its swap, the sync stopped and failing, the source and connectors, HTTPS against a local server, long requests, sync, search, sources, show, `--from` both ways, `parts.json`, supply findings, refresh); `tests/cli.rs`'s `the_jlc_catalogue_from_the_cli` (both ways, against `tests/support/fake_jlc.rs`, a local HTTP site serving the fixture), `a_sync_is_cancelled_by_its_token_and_keeps_the_old_catalogue` and `parts_configure_from_the_cli`, every CLI test with a parts cache of its own; the `parts.jlc.search`, `parts.jlc.show`, `parts.jlc.sources` and `parts.supply` golden lines (a catalogue of the seeded library's offers, `support/parts.rs`' `lcsc_parts`; the determinism harness gives every run an empty cache); the `parts` fuzz target and `tests/bytes.rs` reading jlcparts' files raw and gzipped (`required-features = ["testing"]`); `tests/connectors.rs`.
- **Measured** on cox-worker-3 (Intel Core Ultra 5 250K Plus, 18 threads, shared, load 0.2 to 2.0), release, 2026-11-06. The live sync (`tests/parts_live.rs`, `RYUEDA_PARTS_LIVE=1 cargo test -p ryueda --release --test parts_live -- --ignored --nocapture`, into a temporary cache only): jlcparts' `totalComponents` 370,668; 1,122 files, 31.3 MB downloaded, in 50.1 s (83.3 s for the publication six hours before), one file after another; the index 42.5 MB on disk; peak RSS 1.33 GB. Of 37,192 capacitors, 36,611 have a capacitance, 34,934 a voltage rating, 37,101 a package, 33,827 a tolerance and 15,811 a dielectric; of 71,014 resistors, 70,879 a resistance and 70,735 a power rating. The publication six hours before typed far fewer dielectrics (1,003) and resistor powers (1,103): jlcparts' normalization moves, which this test is for. The bar (`tests/bar.rs`' `the_jlc_catalogue_searches_under_its_bar`, 370,668 seeded parts, one thread, `RYUEDA_BARS=1`, three runs): the first search, loading the capacitors, 272 to 277 ms; the worst of five after it 6.9 to 7.3 ms (bar 500 ms); RSS 732 MB (six runs, three after the seeded values were made from their text).
- **Limits.** No lifecycle until 6.C. Optoelectronics' parts that aren't LEDs read as `led`. A catalogue loaded is held in memory a category at a time. A sync is the whole catalogue each time, one file at a time.
