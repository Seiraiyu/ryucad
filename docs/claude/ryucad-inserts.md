## Inserts and deleted bodies (decided in ryucad phase 25)

The design is document 521 in the Coxswain planning project `ryucad-ryukei`; this is its plan 25.A (phases 1 to 4, issue #41).

- **Solid keys.** A solid's key is an `Id` that may hold `/`: a founder's ID, or an inserted solid's `<insert>/<source key>` (`Id::solid_path`, read by `Id::solid_key`; `Id::parse` still refuses `/`). Every field naming a solid reads it through `doc::solid::SolidRef` (`targets`, `target`, `tools`, a mirror's `solid`, a split's `target` and `tool.body`, the tweak family's `target`, `delete_body`'s `solids`; sheet metal's `target` stays a founder). A reference into an inserted solid is `{feature: <insert>, solid: <source key>, name}` in files, `<part>/<insert>/<source key>/<name>` in text; in memory `Reference::feature` is the key. What reads a key as a feature (list order, the graph, `has_dependents`, renumbering) reads its founder (`Id::founder_str`). Feature format 21 holds inserts, deletes and any path key or `solid`; every other file keeps its bytes (`tests/corpus.rs` writes every committed feature file back byte for byte).
- **Inserts.** `insert` (`doc::insert::Insert`: `part`, `rev` as an instance's, `project` beside it for another project's, `placement` a primitive's, the identity unwritten) founds a *family* (`solid::Solids`): any key below it is its, chain `[insert]` until a feature acts on it; which keys exist is the source's model at the pin. Parts that insert read parts (`assembly::reads_parts`): built after their sources, keyed by the sources' model hashes, never in the leaf batch, never evicted as leaves; Tarjan takes inserts as edges, and a cycle through one is `insert_cycle`. An inserted solid is the source's body moved (`Body::transformed`), its hash BLAKE3 of the source's hash and the pose (`insert::inserted_hash`), the source's own `Arc` at the identity; it carries `Built::moved` so its mesh is the source's moved (`mesh::make`), and the source lineage moved (`Lineage::moved`) so a source split is followed as `Carrier`. Not on disk. Refusals: `not_found`, `wrong_part_kind` (an assembly, question 625), `insert_cycle`, `label_not_found`, `label_not_official`, `insert_source_empty`; warnings `insert_source_failed` (the source's model as it shows) and `insert_obsolete`, under the insert in the report and in the part's warnings. An inserted reference is refused `reference_body` with the hint `ryucad import convert <source part>/<source key>`: it is converted where it was imported.
- **Pins.** A new insert with no `rev` takes the newest official label, else `working` (question 624; the answer's `took`); another project's part takes the lock's newest label, else the fetched dependency's (`release::newest_official`). A request or a proposed part reading a label no file reads yet looks it up (`Session::model`, `Session::rebuilt_as`). `insert.update` (`ryucad insert update <part> <insert> [--to working|label:L|newest] [--dry-run]`, two arguments as `feature edit` takes them) moves it as one logged change, answering the inserted solids `added`, `removed`, `changed` and the features that fail after. `insert_behind` (doctor and check, a warning) has the repair `insert_update`; an insert whose source part is gone is doctor's `not_found` (an error, no repair). Another project's inserted part is locked as a placed one is (ryupdm's `lock::wanted`, `deps::keep_lock`).
- **Deletes.** `delete_body` (`doc::body::DeleteBody`: `solids`, keys or an insert's ID for its family, each once) ends chains as a boolean ends its tools': features before it read them, after it `body_deleted` (`solid`, `by`); deleting a solid twice, a consumed one or one that isn't there is refused at write (`check_delete` runs the build against the current rebuild). It builds to nothing, keyed by its fields, kept in memory; its report's `delete_body.solids` expands an insert's ID to its keys. The CLI's `--solid` repeats: one goes as `solid`, several as `solids`. The model, meshes, exports, mass and check leave deleted solids out.
- **Git and PDM.** Textconv `insert = pcb @ label B` and a placement line, a reference with `solid` as `<feature>/<solid>/<name>`; a merge takes an insert's `rev` and its `placement` as one value each and a delete's `solids` as one; renumbering an insert rewrites every key and reference it begins; `merge_broke` blames a reader of an inserted solid on the side that changed the source (validate's `places` holds inserts). `part.delete` of a part inserted at working is `has_dependents` (`inserted_by`). Releasing a part needs its inserts at official labels that aren't obsolete (`insert_not_released`). Where-used lists inserting parts as `{kind: insert, part, feature, rev}`, working and released (any part's release, not only assemblies'); `deps uses` lists foreign inserts under its own `inserts` key, beside the rows the service indexes by assembly; BOMs never count an insert. `check` doesn't check an inserted solid nothing acted on again: it is its source's.
- **Testing.** Unit tests per module; `tests/inserts.rs` (issue #41's workflow against an exact volume, pins followed and held, a source split followed, a flattened reference refused and converted, two and nested inserts, cycles, a failing source); `tests/deps.rs`' foreign insert, its where-used and `deps uses`; `tests/recompute.rs`' `inserts_and_deletes_recompute_as_from_nothing`; `inserts_and_deletes_from_the_cli` both ways; the `inserts` and `body_deletes` golden sections (`deletes` was already face deletes'); the `feature` fuzz target's `insert.json` and `delete-body.json` seeds (built in a project of `src` and `fz`) and the `merge` target's `0xe6` mode; `tests/insert_bar.rs` (`RYUCAD_PCBA`: 1,201 inserted reference bodies of the owner's ES-10092 board, a warm rebuild after a placement edit 1.159 s with nothing meshed again, on cox-worker-4's Opteron 6380 at load ~50 without `RYUCAD_BARS`; the 1 s bar wants a quiet box). The mesh cache evicts moved meshes before any the kernel made, so a board's sources outlive their moved copies at the default 256 MiB.
- **Left for 25.C.** Instance patterns driven by features and points. 25.B (inserts and deletes in the app, a flattened part's tree collapsed per file) is in `ryucad-app.md`'s "Inserts in the app".
