## Live session (decided in ryucad phase 1)

The design is document 28 in the Coxswain planning project `ryucad-ryukei`.

- **Use model.** Agents model; humans watch, point, judge and nudge. Parity: everything the app can do is a `proto` method with a CLI command (a test fails otherwise), and a human's edit goes through the same request, with `expected_revision`, as an agent's. State lives in five layers: the model and project knowledge in Git, org standards (later, ryupdm), user preferences in the OS config folder, and session state in the daemon. A setting goes in Git only if someone checking out a commit needs it to rebuild or understand the model.
- **Participants.** A connection says `session.hello` as a human (an app window, gone with its last connection) or an agent (reused by name across CLI calls: `--as`/`RYUCAD_PARTICIPANT`, `agent` by default, kept 10 minutes). Each has its own selection, camera, highlights (style `pending`/`changed`/`note`, replaced by style and label) and status. "The human" is the one human attached; with several, `ambiguous_participant`. Entity references are `<part>/<feature>/<32 hex>` everywhere and never resolve to a nearest match; references that stop resolving drop out after a rebuild.
- **Notifications.** `subscribe` turns a connection into a subscription; each has a queue drained by its writer thread, and past 1000 queued it gets one `resync`. Notifications carry state: `model.changed`, `project.changed`, `config.changed`, `participant.changed`, `activity.appended`, and only changes made after subscribing. While anyone is subscribed, the daemon runs its freshness check every `daemon.poll_ms` (250 ms). `ryucad watch` lets an agent wait for them.
- **Activity and undo.** The daemon logs every change it makes (who, the method, each file before and after) and every change it sees behind its back (`external`, not undoable), keeping 1000 entries or 64 MiB. `undo`/`redo` restore files only if every touched file is still as the entry left it (else `undo_conflict`), and are logged themselves. The log is memory only; Git is the history, read with `gix` (no commits, no network; see Diff and check for the config ryucad writes).
- **Settings.** A fixed schema in `config`: `default_unit` in `ryucad.json` (a logged, undoable file change guarded by the project revision), everything else in `preferences.json` under the OS config folder (`RYUCAD_CONFIG_DIR` overrides it); a file that can't be read is reported, used as defaults, and kept as `.bak` when next written; a preference set to its default is removed, so it reads as the default.
- **Meshes and renders.** Display meshes come from `display.quality` (chord a fraction of the body's diagonal), cached by body hash and quality, missed bodies meshed in parallel. `mesh.get` answers JSON, or with `transfer: binary`, `ryucad.mesh.1` bytes after the response line (`binary: {encoding, length}`); renders are always bytes. `render` is a CPU rasterizer in `ryucad::render`: twice the size averaged down, parallel bands, f32 pixel arithmetic, normal display quality and a fixed theme whatever the user's preferences, so its pixels are golden-tested on every platform. Cameras that frame the model (renders, `camera --view/--fit`, the app's first view, standard views and Zoom to fit) fit its mesh points, not its box: centred as the view sees them (in perspective, the extremes each way at equal angles), with a margin, at the view's aspect where it is known (square for `camera`, whose followers may be any shape).
- **Doctor.** `doctor` reads the folder directly (it works with no manifest; a folder with parts but no manifest is `project_damaged`); the checks that rebuild (assemblies' poses, sketches that read other features) use the daemon's session, which is current, else one session opened on the folder (`doctor::Builds`; #125). It reports 20 issue codes, each with planned repairs: exact file changes, an ID with a hash of the files involved (`repair_conflict` if they changed), and parameters (`unit`, `order`). Repairs restore from Git `HEAD` where they can, and never rename (that would change stable names).

## Measure, mass and materials (decided in ryucad phase 10)

The design is document 198 in the Coxswain planning project `ryucad-ryukei`; this is its phase 2, plan 10.A.

- **Materials.** `materials.json` beside the manifest (kind `ryucad.materials`, format 1, `doc::materials`): `materials: {<name>: {density, colour?}}` and an optional `default` naming one. Densities are literals read by `Quantity::density` (`7850 kg/m^3` or `7.85 g/cm^3`, kept as written, positive; `Dim::MASS` and `Dim::DENSITY` are named `mass` and `density`, never read in expressions); names are one line of 1 to 64 characters, colours `#rrggbb` lower case. It is a root file (`ROOT_FILES`), counted in the project revision (tagged), and defines nothing a rebuild reads (`Project::reload` skips it). A part's material is its PDM `material` property's entry, else the default. `materials.list`, `materials.set` (a colour left out keeps its own; `default: true` makes it the default) and `materials.delete` (`has_dependents` while a part names it; the default goes with it, the file with its last material), CLI `ryucad materials list|set|delete`, each write one logged, undoable change guarded by the project revision. Doctor reports `material_unknown` (a warning, no repair) for a part whose material the library lacks, only when there is a library.
- **`measure`.** `measure` (`ryucad measure <ref> [<ref>] [--rev REV]`, `crate::measure`): references resolve through `EntityRef::resolve` (its faults) to placed bodies (`measure::locate`): an entity, `<part>/<solid>` (the solid), or `<asm>/<path>` (every solid of the occurrence), an occurrence's entity placed by its pose. One reference gives ryukei's properties, points and directions placed; several solids their volumes and areas summed. Two give the distance (the least over every pair of solids, its bound down to the least lower end), both nearest points and, where both have directions, the angle and its supplement. A value is `{"value": "12.5 mm", "m": 0.0125, "exact": true}` or with `"bound_m"` (`m2`, `m3`, `rad`, `kg`, `kg_m2` likewise), the text in the project's default unit to ten significant digits; a point `{"m": [..], "value": "(1 mm, 2 mm, 3 mm)"}`. A kernel refusal is `measure_failed` with `reason` (`not_an_entity`, `unsupported`, `uncertain`), `kernel` and `entities`; a sketch entity is `invalid_param`.
- **`mass`.** `mass` (`ryucad mass <of> [--tolerance REL] [--rev REV]`, `crate::mass`): `of` a part or an assembly (every occurrence at its pose), a solid or an occurrence. Each solid at its part's density (1 where it has none, for the geometry); volumes, areas and masses add, centres average by mass (by volume while any density is missing), inertias rotate by each pose and move to the common centre by the parallel axis theorem, bounds add. Mass and inertia (kg m², about the centre, with principal moments and axes from `ryukei::measure::principal`) appear only when every part has a density; otherwise a `material_missing` warning per part, lifted to the CLI's envelope. Per-part rows give solids, material, density and mass. The session keeps results by body hash, density and tolerance (`Session::mass`).
- **Testing.** Unit tests in `doc::materials`, `materials`, `measure`, `mass`, `config` (the revision's tagged piece), `doctor`, `diff` and `merge`; `tests/cli.rs`'s `materials_from_the_cli` (with undo) and `measure_from_the_cli`, both ways; the `measure` section of `tests/golden/rebuild.txt` (masses in two materials, clearances, a measure between occurrences, one thread and four).

## Views and navigation (decided in ryucad phase 10)

The design is document 198 in the Coxswain planning project `ryucad-ryukei`; these are its phases 3 and 4, plan 10.B.

- **Directions.** `view::StandardView` names the navigation cube's 26 directions: the six faces as before, and its edges and corners as `Cube([i8; 3])` (the direction towards the eye, each component -1, 0 or 1), named by their faces in the order front/back, top/bottom, left/right (`front_top`, `top_right`, `back_bottom_left`); `iso` is `front_top_right` by another name. `dimetric` is ISO 5456-3's (x and z at one scale, y at half it: towards the eye `(1, -√7, 1)`), `trimetric` `(1, -3, 2)`. `view::STANDARD_VIEWS` lists all 29 by name; up is z, or y looking along z. `camera --view` and `render --view` take every one.
- **Normal to.** `camera.set` takes `normal_to` (CLI `camera --normal-to <face>`), a face of a part's solid or of an occurrence (placed by its pose, through `measure::locate`): the view looks along a planar face's outward normal or a revolved face's axis (a cylinder, cone, torus or revolution), its longest straight edge level (`view::normal_to`: up leans up z, along y where it is level), framing the model or the `fit` entities with the participant's projection. A sphere, spline, swept or pipe face, or anything but one face, is `invalid_param`; `view` and `normal_to` together are `usage`.
- **Named views.** `parts/<part>/views/<id>.json` (kind `ryucad.view`, format 1, `doc::views`): `eye_m`, `target_m`, `up`, and `projection` `perspective` with `fov_deg` or `orthographic` with `height_m`, in the part's (or assembly's) frame, f64 meters with `-0` written `0` (viewer state, as sketch positions are). The ID is a part ID that isn't a standard view's name (`views::RESERVED`, which must equal `STANDARD_VIEWS`' names; `invalid_id`). A part loads its views (`Part::views`, each a file's error in its place, anything else in the folder unknown) and they count in its revision (a tagged piece after the properties, so parts without views hash as before), never in the release content hash, and nothing a rebuild makes reads them. Plan 10.D adds `sections` and `explode` as format 2.
- **Protocol.** `view.list` (a part's, or every part's, each with its camera or its file's error, and each listed part's revision), `view.save` (`camera`, else `participant`'s, else the one human's, else the caller's; replacing a view of that ID, `replaced` in the answer), `view.delete`, `view.rename` (`duplicate_id` if the name is taken), CLI `ryucad view list|save|delete|rename` (`save` takes `--of` or `--eye/--target/--up` with `--fov` or `--ortho`), each write one logged, undoable change guarded by the part's revision (`--expect`). A missing view is the new code `view_not_found`, naming the part and its views.
- **Restoring.** A `view` that names no standard view is a named view, restored exactly as saved: `camera.set` looks in its new `part` (CLI `--part`), else the caller's focus, else the project's model when that is one part; `render` in the part rendered, else the project's model when it is one part; with `fit` it frames those entities keeping the saved direction. So `--view sideways` is now `view_not_found`, where it was `invalid_param`. A render at a revision reads that revision's views.
- **Origin.** `render --origin` (proto `origin`) draws the origin's axes (red, green and blue, as the triad) and its planes (dashed squares, three quarters of the axes' length each way), a tenth of the drawn model's diagonal long (`render::origin_size`, 5 mm with nothing drawn; `Geometry::add_origin`), depth-tested, and frames them with the model.
- **Preferences.** `display.nav_cube` and `display.triad` (default true) and `display.origin` (default false) say what the app draws over its viewport.
- **Testing.** `view.rs`, `doc::views`, `project.rs`, `views.rs` and `server.rs` unit tests (every direction frames, names round-trip, normal to a tilted face and a box's faces, a render of a named view, the origin's red), `tests/cli.rs`'s `named_views_from_the_cli` both ways (with undo, `--normal-to` and `--view` in a session), and the `views` section of `tests/golden/rebuild.txt` (renders from edges, corners, dimetric, trimetric and a named view with the origin; cameras normal to a tilted face and to a cone).

## Appearance (decided in ryucad phase 10)

The design is document 198 in the Coxswain planning project `ryucad-ryukei`; this is its phase 5, plan 10.C.

- **Files.** `parts/<part>/appearance.json` (kind `ryucad.appearance`, format 1, `doc::appearance`): a part's file holds `part` (its default), `solids` by founder and `faces` by `<founder>/<name>`; an assembly's holds `occurrences`, by instance path (`<path>`, every occurrence under it) or by an occurrence's solid (`<path>/<solid>`), and nothing else (the other kind's keys are `invalid_document`). Each entry sets any of `colour` (`#rrggbb`, lower case), `opacity` (in `(0, 1]`) and `material: true` (the part's material's colour), never `colour` with `material`, never nothing. It loads with its part (`Part::appearance`, the file's error in its place) and counts in its revision as a tagged piece after the named views, so parts without one hash as before; never in the release content hash, and nothing a rebuild makes reads it.
- **Resolution.** `crate::appearance` works each face's colour and opacity out one at a time, from the most specific entry that sets them: the assemblies' entries over an occurrence, outermost first (each its entry for the occurrence's solid, then its path from the longest to the shortest; subassemblies with paths from themselves), then the part's face, solid and part entries. A colour ends at the first entry with `colour` or `material`; with none it is the part's material's colour (its PDM `material`, else the library's default, in `materials.json`), else the viewer's own. An opacity with none is 1. An occurrence pinned at a label is drawn with its part's appearance as the working files have it: appearance is never released.
- **Protocol.** `appearance.get` (`ryucad appearance [<part>] [--of P] [--rev R]`): every solid `part` draws (else `participant`'s focus, else the project's model), each `{part, solid, colour?, opacity, faces?}` (`solid` a founder, or an assembly's `<path>/<founder>`, the app's body key; `faces` by name only where they differ), every part it reaches with its revision, and `appearance_unresolved` warnings (lifted into the CLI's envelope). `appearance.set` (`entities`, `colour`, `material`, `opacity`, `unset` of `colour` or `opacity`) and `appearance.clear` (`ryucad colour <ref>… [--colour #rrggbb] [--material] [--opacity X] [--no-colour] [--no-opacity] [--clear] [--expect REV]`), all references in one part, one logged, undoable change guarded by its revision; an entry set to nothing goes, and the file with its last entry. `set` refuses edges, vertices, sketch entities, an assembly itself and an occurrence's faces (`invalid_param`), and what the model doesn't have now (`not_found`); `clear` takes entries out by their text alone, so what the model lost can be cleared.
- **Kept, never moved.** An entry naming a solid not shown, a face gone or a path no longer placed is kept and colours nothing: `appearance.get`'s warning and doctor's `appearance_unresolved` (a warning, no repair; the session's `removed_from` names the feature of the solid's chain that took a face away, as `removed_by`). A file that doesn't read is doctor's `invalid_document`, one not canonical `non_canonical`; the rebuild never reads it.
- **Renders.** `render` draws each face in its appearance unless `appearance: false` (`--no-appearance`), the fixed theme; highlights and a compare's paint replace a face's colour and draw it opaque. Translucent faces are kept per sample in front of the model and blended back to front by depth, ties in the order given (`render::Geometry::translucent`), exactly and on any number of threads; an edge bounding only translucent faces is drawn among them, as opaque as its most opaque face, just in front of it. Opaque lines bring the depth they stop at forward. Existing renders keep their pixels (no golden hash moved).
- **Testing.** `doc::appearance`, `project.rs`, `appearance.rs` (resolution, set and clear, assemblies, materials, unresolved entries with `removed_by`, renders), `render.rs` (translucent order and threads), `doctor.rs` unit tests; `tests/cli.rs`'s `appearance_from_the_cli` both ways, with undo; the `appearance` section of `tests/golden/rebuild.txt` (`appearance.get` of a coloured part and of an assembly over it, and renders in colour, translucent, in the theme, and of the assembly).
