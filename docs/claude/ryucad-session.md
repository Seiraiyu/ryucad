## Live session (decided in ryucad phase 1)

The design is document 28 in the Coxswain planning project `ryucad-ryukei`.

- **Use model.** Agents model; humans watch, point, judge and nudge. Parity: everything the app can do is a `proto` method with a CLI command (a test fails otherwise), and a human's edit goes through the same request, with `expected_revision`, as an agent's. State lives in five layers: the model and project knowledge in Git, org standards (later, ryupdm), user preferences in the OS config folder, and session state in the daemon. A setting goes in Git only if someone checking out a commit needs it to rebuild or understand the model.
- **Participants.** A connection says `session.hello` as a human (an app window, gone with its last connection) or an agent (reused by name across CLI calls: `--as`/`RYUCAD_PARTICIPANT`, `agent` by default, kept 10 minutes). Each has its own selection, camera, highlights (style `pending`/`changed`/`note`, replaced by style and label) and status. "The human" is the one human attached; with several, `ambiguous_participant`. Entity references are `<part>/<feature>/<32 hex>` everywhere and never resolve to a nearest match; references that stop resolving drop out after a rebuild.
- **Notifications.** `subscribe` turns a connection into a subscription; each has a queue drained by its writer thread, and past 1000 queued it gets one `resync`. Notifications carry state: `model.changed`, `project.changed`, `config.changed`, `participant.changed`, `activity.appended`, and only changes made after subscribing. While anyone is subscribed, the daemon runs its freshness check every `daemon.poll_ms` (250 ms). `ryucad watch` lets an agent wait for them.
- **Activity and undo.** The daemon logs every change it makes (who, the method, each file before and after) and every change it sees behind its back (`external`, not undoable), keeping 1000 entries or 64 MiB. `undo`/`redo` restore files only if every touched file is still as the entry left it (else `undo_conflict`), and are logged themselves. The log is memory only; Git is the history, read with `gix` (no commits, no network; see Diff and check for the config ryucad writes).
- **Settings.** A fixed schema in `config`: `default_unit` in `ryucad.json` (a logged, undoable file change guarded by the project revision), everything else in `preferences.json` under the OS config folder (`RYUCAD_CONFIG_DIR` overrides it); a file that can't be read is reported, used as defaults, and kept as `.bak` when next written; a preference set to its default is removed, so it reads as the default.
- **Meshes and renders.** Display meshes come from `display.quality` (chord a fraction of the body's diagonal), cached by body hash and quality, missed bodies meshed in parallel. `mesh.get` answers JSON, or with `transfer: binary`, `ryucad.mesh.1` bytes after the response line (`binary: {encoding, length}`); renders are always bytes. `render` is a CPU rasterizer in `ryucad::render`: twice the size averaged down, parallel bands, f32 pixel arithmetic, normal display quality and a fixed theme whatever the user's preferences, so its pixels are golden-tested on every platform. Cameras that frame the model (renders, `camera --view/--fit`, the app's first view, standard views and Zoom to fit) fit its mesh points, not its box: centred as the view sees them (in perspective, the extremes each way at equal angles), with a margin, at the view's aspect where it is known (square for `camera`, whose followers may be any shape).
- **Doctor.** `doctor` reads the folder directly (it works with no manifest; a folder with parts but no manifest is `project_damaged`); the checks that rebuild (assemblies' poses, sketches that read other features) use the daemon's session, which is current, else one session opened on the folder (`doctor::Builds`; #125). It reports 20 issue codes, each with planned repairs: exact file changes, an ID with a hash of the files involved (`repair_conflict` if they changed), and parameters (`unit`, `order`). Repairs restore from Git `HEAD` where they can, and never rename (that would change stable names).

## Measure, mass and materials (decided in ryucad phase 10)

The design is document 198 in the Coxswain planning project `ryucad-ryukei`; this is its phase 2, plan 10.A.

- **Materials.** `materials.json` beside the manifest (kind `ryucad.materials`, format 1, `doc::materials`): `materials: {<name>: {density, colour?}}` and an optional `default` naming one. Densities are literals read by `Quantity::density` (`7850 kg/m^3` or `7.85 g/cm^3`, kept as written, positive; `Dim::MASS` and `Dim::DENSITY` are named `mass` and `density`, never read in expressions); names are one line of 1 to 64 characters, colours `#rrggbb` lower case. It is a root file (`ROOT_FILES`), counted in the project revision (tagged), and defines nothing a rebuild reads (`Project::reload` skips it). A part's material is its PDM `material` property's entry, else the default. `materials.list`, `materials.set` (a colour left out keeps its own; `default: true` makes it the default) and `materials.delete` (`has_dependents` while a part names it; the default goes with it, the file with its last material), CLI `ryucad materials list|set|delete`, each write one logged, undoable change guarded by the project revision. Doctor reports `material_unknown` (a warning, no repair) for a part whose material the library lacks, only when there is a library.
- **`measure`.** `measure` (`ryucad measure <ref> [<ref>] [--rev REV]`, `crate::measure`): references resolve through `EntityRef::resolve` (its faults) to placed bodies (`measure::locate`): an entity, `<part>/<solid>` (the solid), or `<asm>/<path>` (every solid of the occurrence), an occurrence's entity placed by its pose. One reference gives ryukei's properties, points and directions placed; several solids their volumes and areas summed. Two give the distance (the least over every pair of solids, its bound down to the least lower end), both nearest points and, where both have directions, the angle and its supplement. A value is `{"value": "12.5 mm", "m": 0.0125, "exact": true}` or with `"bound_m"` (`m2`, `m3`, `rad`, `kg`, `kg_m2` likewise), the text in the project's default unit to ten significant digits; a point `{"m": [..], "value": "(1 mm, 2 mm, 3 mm)"}`. A kernel refusal is `measure_failed` with `reason` (`not_an_entity`, `unsupported`, `uncertain`), `kernel` and `entities`; a sketch entity is `invalid_param`.
- **`mass`.** `mass` (`ryucad mass <of> [--tolerance REL] [--rev REV]`, `crate::mass`): `of` a part or an assembly (every occurrence at its pose), a solid or an occurrence. Each solid at its part's density (1 where it has none, for the geometry); volumes, areas and masses add, centres average by mass (by volume while any density is missing), inertias rotate by each pose and move to the common centre by the parallel axis theorem, bounds add. Mass and inertia (kg m², about the centre, with principal moments and axes from `ryukei::measure::principal`) appear only when every part has a density; otherwise a `material_missing` warning per part, lifted to the CLI's envelope. Per-part rows give solids, material, density and mass. The session keeps results by body hash, density and tolerance (`Session::mass`).
- **Testing.** Unit tests in `doc::materials`, `materials`, `measure`, `mass`, `config` (the revision's tagged piece), `doctor`, `diff` and `merge`; `tests/cli.rs`'s `materials_from_the_cli` (with undo) and `measure_from_the_cli`, both ways; the `measure` section of `tests/golden/rebuild.txt` (masses in two materials, clearances, a measure between occurrences, one thread and four).
